# หน้างานปั๊ม (Pressing) — Page Design Spec & Overrides

> **แหล่งอ้างอิงหลัก:** [LThai Design System Master](../MASTER.md)
> **ข้อยุติการสัมภาษณ์:** Q1–Q10 (27 พฤศจิกายน 2026) — ใช้แนวทาง `ui-ux-pro-max` + `ponytail` (นำคลาสและโทเค็นที่มีอยู่แล้วในระบบมาใช้ซ้ำให้มากที่สุด)
> **สถานะ:** รอผู้ใช้ตรวจแบบและยืนยันก่อนเริ่มแก้ไขโค้ด (`apps/web`)

## 1. ขอบเขตและหลักการเฉพาะหน้า (Scope & Guardrails)

- **ครอบคลุมเฉพาะเมนู `งานปั๊ม` 2 แท็บ:** `ใบสั่งผลิต` (`orders.tsx`) และ `บันทึกยอด` (`production.tsx`) รวมถึงแถบสรุปและแถบแท็บใน `pressing/panel.tsx`
- **ไม่แตะหน้าอื่นในรอบนี้:** คง `สต็อกงานปั๊ม` (`inventory.tsx` ในเมนูสต็อก), `ProductPicker` เดิม (รักษาพฤติกรรมค้นหาใน Dropdown + คีย์บอร์ด), `print.css`, API (`/pressing/*`), ฐานข้อมูล และสิทธิ์การใช้งาน (`pressing.read`, `pressing.manage`, `pressing.record`, `pressing.correct`, `finishing.prepare`) ไว้ 100%
- **คำศัพท์และตัวแบบโดเมน ([GLOSSARY.md](../../../GLOSSARY.md)):**
  - ใช้คำศัพท์โรงงานตรงตามทะเบียน: `ใบสั่งผลิต`, `ยอดสั่งปั๊ม`, `ยอดปั๊ม`, `จำนวนไม้เต็ม`, `แผ่นเศษ`, `จำนวนแผ่นต่อไม้`, `วันครบกำหนดพัก` (`ระยะรอคงที่`), `วันที่ปั๊ม`, `กระเบื้องติดตาข่าย`
  - **ป้ายสถานะยอดในตารางใบสั่งผลิต** (`ยังไม่ครบ` / `ครบตามสั่ง` / `ปั๊มเกิน`) เป็น **ป้ายแสดงผลที่คำนวณจาก `short_pieces` และ `over_pieces` เดิม** ไม่ใช่สถานะเอกสารใหม่ในฐานข้อมูล
- **นำ CSS เดิมมาใช้ซ้ำ (Ponytail Reuse):** ใช้คลาสที่มีอยู่แล้วจากชุด `รับดินและวัตถุดิบ` ใน `globals.css` และ `buttons.css` (`.clay-kpi-grid`, `.clay-kpi-card`, `.clay-filters`, `.table-wrap`, `.num-col`, `.status-pill`, `.form-section`, `.form-grid`, `.pressing-dialog`, `.dialog-lg`, `.raw-clay-detail-body`, `.raw-clay-detail-actions`, `.button.primary/secondary/warning/danger-soft/destructive`) โดยเพิ่ม CSS เฉพาะจุดที่จำเป็นจริงเท่านั้น (เช่น กล่องสรุปคำนวณสด และ Empty State)

## 2. แถบสรุป KPI ด้านบน (`PressingKpiStrip`)

วางบนสุดของ `PressingPanel` (แสดงเฉพาะโหมดเมนูงานปั๊ม `!stockOnly`) ใช้โครงสร้าง `.clay-kpi-grid` + `.clay-kpi-card` 3 การ์ด พร้อมไอคอน SVG เส้นบาง `20×20` (`strokeWidth="1.8"`, `aria-hidden="true"`) คำนวณจาก `data.orders` และ `data.entries` ที่โหลดมาอยู่แล้ว ไม่ต้องยิง API เพิ่ม:

| การ์ด | หัวข้อ | ค่าหลัก (`tabular-nums`) | ข้อความรอง | โทนไอคอน |
|---|---|---|---|---|
| 1 | **ใบสั่งที่ยังไม่ครบยอด** | จำนวนใบที่ `short_pieces > 0` (`ใบ`) | `ยอดขาดรวม … แผ่น` (ถ้า 0 แสดง `ครบตามสั่งทุกใบแล้ว`) | `.warn` (อำพัน) |
| 2 | **ยอดปั๊มวันนี้** | ผลรวม `entry.pieces` ที่ `entry.pressed_on === bangkokDate()` (`แผ่น`) | `สะสมทั้งหมด … แผ่น · … รายการ` | `.clay` (ดินเผา) |
| 3 | **ใบสั่งผลิตทั้งหมด** | `data.orders.length` (`ใบ`) | `ออเดอร์ลูกค้า … · เก็บสต็อก …` | `.good` (เขียว) |

> **ข้อควรระวัง:** `ยอดปั๊มวันนี้` เปรียบเทียบด้วย `bangkokDate()` (`Asia/Bangkok`) ให้ตรงกับวันที่เริ่มต้นของฟอร์มบันทึกยอดปั๊ม

#### กติกาแท็บ `ใบสั่งผลิต`
- **ลำดับแถวเริ่มต้น (Q9):** แบ่ง 2 กลุ่มโดยอัตโนมัติ — ใบที่ `short_pieces > 0` (**ยังไม่ครบ**) ขึ้นก่อน แล้วตามด้วยใบที่ครบ/เกิน ภายในแต่ละกลุ่มเรียงตาม `id` มากไปน้อย (ใบใหม่สุดขึ้นก่อน)
- **ตัวกรองฝั่งหน้าเว็บ (Q4):**
  1. `ค้นหา`: จับคู่แบบไม่สนตัวพิมพ์กับ `orderName(order)`, `customer_reference`, `product_code`, `product_name`, ชื่อประเภทดิน/สีดิน, `color_name`
  2. `ที่มา`: `ทั้งหมด` | `ตามออเดอร์ลูกค้า` (`customer`) | `ผลิตเก็บสต็อก` (`stock`)
  3. `สถานะยอด`: `ทั้งหมด` | `ยังไม่ครบ` (`short_pieces > 0`) | `ครบตามสั่ง` (`short_pieces === 0 && over_pieces === 0`) | `ปั๊มเกิน` (`over_pieces > 0`)
- **ป้ายสถานะยอด (`.status-pill` — สี + ขอบ + จุด + ข้อความ):**
  - `ยังไม่ครบ`: โทนเตือน `.status-pill.draft` (อำพัน — สื่อว่าต้องปั๊มต่อ)
  - `ครบตามสั่ง`: โทนสำเร็จ `.status-pill.confirmed` (เขียว)
  - `ปั๊มเกิน`: โทนกลาง `.badge.neutral` หรือ `.status-pill.neutral` (เทา-เขียวอ่อน + จุดสีชัดเจน)
- **คอลัมน์ `จัดการ`:**
  - ปุ่มลัด `บันทึกยอด` (`.button.secondary`) — แสดงเฉพาะเมื่อผู้ใช้มีสิทธิ์ `pressing.record` และประเภทกระเบื้องของใบสั่งยัง `active` และมีพนักงาน `data.workers.length > 0` กดแล้วเปิด Modal `บันทึกยอดปั๊ม` โดยเลือกใบสั่งผลิตใบนั้นให้ล่วงหน้าทันที (Q8)
  - ปุ่ม `เปิด` (`.button.secondary`) — เปิด Modal รายละเอียดใบสั่งผลิตขนาด `lg`
  - **ไม่วางปุ่มแดง (`ลบใบสั่งผลิต`) หรือปุ่มส้ม (`แก้ยอด`, `เติมข้อมูลใบค้าง`) บนแถวตาราง** เพื่อลดความรกและป้องกันการกดพลาด
- **หน้าว่างนำทาง (Guided Empty State — Q9):**
  - กรณี **ยังไม่มีใบสั่งผลิตในระบบเลย**: แสดงกรอบข้อความนำทางสั้น 1–2 บรรทัด (`ยังไม่มีใบสั่งผลิต — เริ่มต้นด้วยการเพิ่มใบสั่งผลิตใบแรกเพื่อเปิดงานปั๊ม`) พร้อมปุ่มหลัก `.button.primary` `＋ เพิ่มใบสั่งผลิตใบแรก` (ตามสิทธิ์ `pressing.manage`) หากยังไม่มีสินค้าพร้อมผลิต ให้คงข้อความแนะนำไปตั้งค่าที่ `หมวดหมู่ → ทะเบียนกระเบื้อง` ตามเดิม
  - กรณี **กรองแล้วไม่พบรายการ**: แสดง `ไม่พบใบสั่งผลิตตามตัวกรอง` พร้อมปุ่ม `.button.secondary` `ล้างตัวกรอง`

```text
|------------|------------------------|--------------|---------------:|--------------:|------------|------------------|
| 2026-11-27 | ใบสั่ง #12 · OD-041     | สมชาย ใจดี    | 25 ไม้ + 20 แผ่น |        620    | 2026-11-30 | [เปิด / ประวัติ]  |
| #24        | LT-411 · ดินขาว         |              |                |               |            |                  |

| #23        | LT-205 · ดินศิลาแลง     |              |                | เดิม 800 แผ่น  |            |                  |
+---------------------------------------------------------------------------------------------------+
```

#### กติกาแท็บ `บันทึกยอด`
- **ปุ่มหลักด้านบน:** ใช้ `.button.primary` (`＋ บันทึกยอดปั๊ม`) แทน `.button.success` เดิมให้เป็นมาตรฐานเดียวกันทุกหน้า
- **ลำดับแถวเริ่มต้น:** เรียงรายการล่าสุดขึ้นก่อน (`[...entries].reverse()`) ตามเดิม
- **ตัวกรองฝั่งหน้าเว็บ (Q4):**
  1. `ค้นหา`: จับคู่ชื่อผู้ปั๊ม (`employee_name`), ชื่อใบสั่งผลิต/เลขอ้างอิง, ชื่อสินค้า/ดิน, หมายเหตุ (`note`), หรือรหัส `#id`
  2. `ใบสั่งผลิต`: Dropdown (`ทุกใบสั่งผลิต` + รายการใบสั่งทั้งหมด)
  3. `ตั้งแต่วันที่` / `ถึงวันที่`: กรองตาม `entry.pressed_on` (`YYYY-MM-DD`)
- **คอลัมน์ `ยอดปั๊ม (แผ่น)`:** แสดงตัวเลขหนา `tabular-nums` และหาก `entry.original_pieces !== entry.pieces` แสดงบรรทัดรอง `.subtext` ว่า `เดิม … แผ่น` ให้เห็นทันทีว่ารายการนี้เคยผ่านการปรับยอด
- **หน้าว่างนำทาง (Guided Empty State — Q9):**
  - กรณี **ยังไม่มีใบสั่งผลิตเลย**: แสดง `ยังไม่มีใบสั่งผลิตสำหรับบันทึกยอด` พร้อมปุ่ม `.button.primary` `ไปที่ใบสั่งผลิตเพื่อเพิ่มใบแรก` (สลับแท็บไป `ใบสั่งผลิต` หรือเปิดฟอร์มเพิ่มใบสั่งหากมีสิทธิ์ `pressing.manage`)
  - กรณี **มีใบสั่งผลิตแล้วแต่ยังไม่มีรายการปั๊ม**: แสดง `ยังไม่มีรายการปั๊ม` พร้อมปุ่ม `.button.primary` `＋ บันทึกยอดปั๊มรายการแรก` (ตามสิทธิ์ `pressing.record`)
  - กรณี **กรองแล้วไม่พบรายการ**: แสดง `ไม่พบรายการปั๊มตามตัวกรอง` พร้อมปุ่ม `.button.secondary` `ล้างตัวกรอง`

### 4.3 Modal เพิ่มใบสั่งผลิต (`size="lg"` · `800px`)

ขยายจาก `md` เป็น `lg` และจัดกลุ่มช่องกรอกด้วย `.form-section` 3 ส่วน เหมือนฟอร์มรับดิน:

1. **ส่วนที่ 1 — ที่มาและรายการสินค้า / ประเภทดิน**
   - `ที่มาของใบสั่งผลิต` (`ตามออเดอร์ลูกค้า` / `ผลิตเก็บสต็อก`) + `งานที่สั่งเก็บสต็อก` (เมื่อเลือกเก็บสต็อก)
   - `รายการสินค้าและรุ่น` (`ProductPicker` เดิมที่ค้นหาใน Dropdown ได้)
   - `ประเภทดิน` + `สีดินที่ผสมในเนื้อดิน` (เมื่อเลือกดินสี) หรือ `ประเภทดิน / สีที่ผสม` (กรณีดินพื้น)
2. **ส่วนที่ 2 — เลขอ้างอิง สีเคลือบ และจำนวนสั่ง**
   - `เลขอ้างอิงออเดอร์` / `เลขอ้างอิงงานสั่งเก็บสต็อก`
   - `สีเคลือบ` (เมื่อปลายทางเป็นงานสี)
   - `ยอดลูกค้าสั่ง (แผ่น)` + `เปอร์เซ็นต์เผื่อ (5–20%)` หรือ `ยอดสั่งเก็บสต็อก (แผ่น)`
3. **ส่วนที่ 3 — สรุปค่ามาตรฐานและยอดสั่งปั๊มคำนวณสด**
   - กล่อง `Facts` แสดง `แผ่นต่อไม้`, `วันพัก`, `แผ่นต่อ ตร.ม.`, `ปลายทาง`, `ยอดเผื่อ`, `ยอดสั่งปั๊ม (แผ่น)`, `พื้นที่สั่งปั๊ม (ตร.ม.)`

### 4.4 Modal บันทึกยอดปั๊ม (`size="md"` · `560px`) พร้อมกล่องคำนวณสด (Q8)

จัดกลุ่มเป็น `.form-section` 2 ส่วน + กล่องคำนวณสดก่อนกดยืนยัน (`.info-banner` หรือ `.form-section` สรุป):

1. **ส่วนที่ 1 — ใบสั่งผลิตและผู้ทำงาน**
   - `ใบสั่งผลิต` (ถูกล็อกค่าเริ่มต้นให้ทันทีหากกดมาจากปุ่มลัดของใบสั่งผลิต แต่ยังเปลี่ยนได้ก่อนบันทึก)
   - `วันที่ปั๊ม` (`defaultValue = bangkokDate()`) + `ผู้ปั๊ม` (จัด 2 คอลัมน์ `.form-grid`)
2. **ส่วนที่ 2 — จำนวนที่ปั๊มได้และหมายเหตุ**
   - `จำนวนไม้เต็ม` + `แผ่นเศษ` (จัด 2 คอลัมน์ `.form-grid`)
   - `หมายเหตุ`
3. **กล่องสรุปคำนวณสดก่อนยืนยัน (Live Preview — ตรงสูตร API 100%):**
   - สูตรคำนวณเทียบกับ `apps/api/src/pressing/stock.ts` (`recordEntry` + `restEnd`):
     - `piecesPerRack = order.production_pieces_per_rack ?? tile.pieces_per_rack`
     - `restDays = order.production_rest_days ?? tile.rest_days`
     - `pieces = fullRacks * piecesPerRack + loosePieces`
     - `readyOn`: คำนวณด้วย UTC date arithmetic จาก `pressedOn + "T00:00:00Z"` แล้ว `setUTCDate(+restDays)` คืนค่า `YYYY-MM-DD` (ตรงกับ `restEnd` ของ API ทุกกรณี ไม่มีเพี้ยนตาม Timezone)
   - ข้อมูลที่แสดงในกล่องสรุป:
     - **ยอดปั๊มครั้งนี้:** `… แผ่น` (`… ไม้ × … แผ่น/ไม้ + … แผ่นเศษ`) และ `ตร.ม.` หากมีค่า `pieces_per_sqm`
     - **ผลต่อใบสั่งผลิต:** `ปั๊มแล้ว … → … / สั่ง … แผ่น` (ระบุชัดว่ายังขาดอีกกี่แผ่น หรือครบ/เกินกี่แผ่น)
     - **วันครบกำหนดพัก:** `YYYY-MM-DD` (`พัก … วัน`)
   - ใช้กล่องสรุปแบบเดียวกันใน Modal `แก้รายการปั๊ม` (`edit`) โดยอ้างอิง `entry.pieces_per_rack` และ `restDays` ของใบสั่งเดิม

### 4.5 Modal ฟอร์มสั้นอื่น ๆ (`size="md"` · `560px`)

- `แก้ยอดสั่งปั๊ม` (`PUT /pressing/orders/:id`): `size="md"`, ปุ่มยืนยัน `.warning`
- `เติมข้อมูลใบค้าง` (`POST /finishing/prepare-order`): `size="md"`, ปุ่มยืนยัน `.warning`
- `ปรับยอดหลังเคลื่อนไหว` (`POST /pressing/entries/:id/adjustments`): `size="md"`, ปุ่มยืนยัน `.warning`
- `ลบใบสั่งผลิต` (`DELETE /pressing/orders/:id`): `size="md"`, ปุ่มยืนยัน `.destructive`

## 5. แผนการรองรับหน้าจอและ Accessibility (`ui-ux-pro-max` Checklist)

- **ความชัดเจนของตัวเลขและข้อความ:** ฟอนต์ฐาน `15px`, ข้อความรอง `≥ 13.5px`, ตัวเลขใน KPI/ตาราง/สรุปคำนวณใช้ `tabular-nums` และชิดขวาในคอลัมน์ตัวเลข (`.num-col`)
- **ห้ามพึ่งสีอย่างเดียว:** ป้ายสถานะทุกจุดมีทั้งสีพื้นอ่อน + เส้นขอบ + จุดสี + ข้อความภาษาไทย; ไอคอนใน KPI ใช้ inline SVG พร้อม `aria-hidden="true"` (ไม่ใช้ Emoji แทนไอคอน)
- **Responsive:**
  - Desktop `1280px–1440px`: ตาราง 7 คอลัมน์แสดงครบไม่ต้องเลื่อนแนวนอน, ตัวกรอง `.clay-filters` เรียงแถวเดียว
  - Tablet/Mobile `≤ 760px`: ตัวกรองยุบลงคอลัมน์อัตโนมัติ, ตารางเลื่อนแนวนอนได้ใน `.table-wrap`, Modal กว้างเต็ม `calc(100% - 24px)` สูงสุด `92dvh`
- **Keyboard & Contrast:**
  - ปุ่ม, ช่องกรอก, Dropdown สูง `≥ 40px` พร้อม `:focus-visible` ชัดเจนทั้ง Light/Dark Mode
  - Contrast ทุกคู่ใช้ตัวแปรจาก `theme.css` / `buttons.css` ที่ตรวจผ่าน WCAG AA (≥ 4.5:1) ทั้ง Light และ Dark
  - คง `guardDismissal`, `beforeunload` warning, และ idempotency (`request_id`) ใน `FormDialog` เดิม 100%
