# ตรวจรับทะเบียนประเภทดิน

สถานะ: นำขึ้นระบบจริงวันที่ 23 พฤศจิกายน 2026 แล้ว ที่ http://127.0.0.1:3001 ด้วย commit `0b41559` ทะเบียนดิน4ประเภทและสีดินว่าง ผู้ใช้ยืนยันไม่ย้ายสีทดลอง `test-001` “แกนิต” หรือข้อมูลทดลองอื่น สำรองหลัก/QAพร้อม checksum และปิด QA แล้ว รายละเอียดสำรองและผลตรวจอยู่ใน `docs/CURRENT.md`

ใช้งานจริงที่ **หมวดหมู่ → ทะเบียนประเภทดิน** และตั้งค่าผลิตจริงจากทะเบียนกระเบื้องก่อนเปิดใบสั่งสินค้า เนื้อหาการตรวจ QA ด้านล่างเก็บเป็นประวัติ URL3150/4150และบัญชี QA ใช้งานไม่ได้แล้ว ห้ามใช้ค่าผลิตตัวอย่างเป็นค่าจริงของโรงงาน

## เข้าใช้งาน QA (ประวัติ — ปิดแล้ว)

- เว็บ QA: http://localhost:3150 ใช้ localhost เพื่อแยก cookie จากเว็บหลักที่ใช้ 127.0.0.1:3001
- บัญชีทดสอบอยู่ในไฟล์ส่วนตัว `.qa/clay-registry/login.json` ไม่อยู่ใน Git บัญชีนี้สร้างเฉพาะ QA ไม่แก้บัญชีเดิม
- QA ใช้ฐาน/role `lthai_clay_registry_qa` และ Docker project `lthai-clay-qa` แยกจากหลัก

## 1. ทะเบียนประเภทดิน

ไป **หมวดหมู่ → ทะเบียนประเภทดิน** ต้องเห็น ดินขาว ดินสี ดินแดง และศิลาแลง แก้ชื่อ คำอธิบาย และสถานะใช้งานได้ตามสิทธิ์ รหัสอ้างอิงเดิมไม่เปลี่ยนตามชื่อ

สีดินเริ่มว่างตามข้อตกลง ไม่มีสีหรือสูตรสมมติ หากข้อมูลพร้อมจึงกดเพิ่มสีดิน ระบุรหัสและชื่อ สีดินที่ผสมในเนื้อดินแยกจากชาร์ตสีเคลือบผิว ไม่ต้องใส่อุณหภูมิหรืออัตราส่วนผสมในงานนี้

## 2. ตั้งค่าผลิต

ไป **หมวดหมู่ → ทะเบียนกระเบื้อง** ค้น `QA-CLAY-DEMO` แล้วกด **ตั้งค่าผลิต**

รายการนี้เป็นสินค้าทดสอบเพิ่มขึ้นเฉพาะ QA จากทะเบียนจริง161รายการ รวมเป็น162รายการ ค่าตัวอย่างดินขาว ดินแดง และศิลาแลงคือ40แผ่นต่อไม้/พัก0วัน/90แผ่นต่อ ตร.ม./เข้าเตาบรีส ตัวเลขนี้ใช้ทดสอบเท่านั้น ไม่ใช่ข้อมูลโรงงานและไม่ย้ายขึ้นหลัก

การตั้งค่าของสินค้าอื่นต้องยืนยันแบบดินปั๊มจริง หรือเลือกสร้างแบบของรายการนั้น แล้วกรอกค่าผลิตจริง ไม่จับคู่สินค้าจากขนาดโดยอัตโนมัติ หากเลือกใช้แบบร่วม หน้าจอแสดงรหัสสินค้าและเลขรายการที่จะใช้ค่าผลิตชุดเดียวกันก่อนบันทึก

กรณีมีค่าผลิตดินสีเก่าที่รอจับคู่ ระบบบล็อกการสร้างซ้ำและแจ้งให้ตรวจยืนยันก่อน ไม่รวมชื่อสีคล้ายกันอัตโนมัติ ข้อมูล QA ที่กู้มารอบนี้ไม่มีรายการดินสีเก่าที่ต้องจับคู่

## 3. ใบสั่งผลิต

ไป **งานปั๊ม → ใบสั่งผลิต → เพิ่มใบสั่งผลิต**

1. ค้น `QA-CLAY-DEMO` แล้วเลือกรายการสินค้า
2. เลือกดินขาว ดินแดง หรือศิลาแลง จะเห็นค่าผลิตของประเภทนั้น
3. เลือกดินสี จะเห็นข้อความว่ายังไม่มีสีดินให้เลือกและยังบันทึกไม่ได้
4. กรอกข้อมูลออเดอร์และจำนวน ระบบบันทึกชื่อดิน/สีดินและค่าผลิต ณ วันที่สร้างใบสั่ง

มีใบตัวอย่าง `QA-CLAY-DEMO-ORDER` ดินขาว ยอดลูกค้า100แผ่น เผื่อ10% รวม110แผ่น สร้างไว้ผ่าน UI แล้วเฉพาะ QA ยังไม่ได้ลงงานผลิตจริงของโรงงาน

หากแก้ชื่อหรือหยุดใช้ดินภายหลัง ใบเก่ายังคงชื่อเดิมและดำเนินงานต่อได้ แต่ใบใหม่เลือกประเภทที่หยุดใช้ไม่ได้ หากมีคนแก้ประเภทดินของค่าผลิตระหว่างเปิดฟอร์ม ระบบแจ้งให้โหลดใหม่แทนการใช้ดินอีกประเภทโดยเงียบ ๆ

## 4. เรื่องที่พักไว้

- ข้อมูลสีดินจริง ให้เพิ่มเมื่อโรงงานเรียบเรียงพร้อม
- ข้อมูลช่วงอุณหภูมิใหม่/รายสี ยังไม่ตั้งหรือคาดเดา ระบบเข้าเตาตรวจช่วงเดิมตามปกติ ข้อมูลไม่ครบยังถูกบล็อก
- สูตรผสม เปอร์เซ็นต์สี การผสมเป็นล็อต และการตัดสต็อกวัตถุดิบไม่อยู่ในรุ่นนี้

## ผลตรวจของผู้พัฒนา

- สำรองหลักใหม่และกู้เป็น QA ตรวจ target/role แล้ว ก่อนรัน migration/tests
- ข้อมูลเดิม43ตารางตรงกันก่อน/หลัง migration สองรอบ; ทะเบียนนำเข้า161รายการคงเดิม เพิ่มเฉพาะข้อมูล QA ที่ระบุข้างต้น
- ทดสอบ API118ผ่าน0ล้ม9ข้าม, เว็บ46ผ่าน0ล้ม, legacy14ผ่าน0ล้ม รวม178ผ่าน0ล้ม9ข้าม
- 5กรณีข้ามต้องมี Excelสีส่วนตัว อีก4กรณีเป็น importer integration ที่ผูกกับฐาน QA ทะเบียนกระเบื้องรุ่นก่อนซึ่งปิดแล้ว จึงไม่รื้อฟื้นฐานนั้นเพื่อทดสอบงานดิน ผลทดสอบเหล่านี้ไม่ได้ถูกนับเป็นผ่าน
- ทดสอบเพิ่มเติมเรื่อง transaction ย้อนกลับทั้งชุด, การบันทึกพร้อมกัน, snapshot, สีต่างกันใช้สต็อกร่วมไม่ได้, เปลี่ยนชื่อแล้วยังคงรหัสดินสำหรับเข้าเตา, migrationซ้ำ และสิทธิ์อ่านอย่างเดียว
- Typecheck และ Docker API/web buildผ่าน; ตรวจ UI ตั้งค่า/เปิดใบสั่ง/สีว่าง/ขนาด390px และ health ของ QA/หลักผ่าน ผู้รีวิวอิสระตรวจและยืนยันปิดประเด็นสำคัญแล้ว
