อัปเดต: 12 พฤศจิกายน 2026

## เป้าหมาย

ระบบโรงงานกระเบื้องภาษาไทย มีข้อมูลพนักงาน บัญชี บทบาท สิทธิ์ และประวัติการเปลี่ยนแปลง เพิ่มงานปั๊มรุ่นแรกบนสาขา `codex/pressing-v1` ใช้ Next.js/React/Tailwind, Express/TypeScript และ PostgreSQL

## งานปัจจุบัน: ชาร์ตสีรุ่นแรก

สาขา `codex/color-chart` พัฒนาชาร์ตสีตาม [แบบที่ยืนยัน](superpowers/specs/2026-11-12-color-chart-design.md) และ [แผนพัฒนา](superpowers/plans/2026-11-12-color-chart.md) โค้ดล่าสุดของฟีเจอร์คือ `1182189` เพิ่มเมนูค้นชื่อไทยและอังกฤษ ให้สิทธิ์ดูหรือจัดการผ่านบทบาทเดิม และเก็บภาพตัวอย่างหนึ่งภาพต่อรายการใน PostgreSQL เพื่อให้กู้คืนพร้อมทะเบียนได้

- งานนำเข้าอยู่ใน `scripts/extract-color-chart.py` และ `apps/api/src/color-chart/` หน้าเว็บอยู่ใน `apps/web/src/components/color-chart/` คำสั่งตรวจและนำเข้าอ่าน Excel ซ้ำด้วย `openpyxl==3.1.5` และเทียบกับ JSON โดยตรง รุ่น `d7eecef` ตรวจ Excel จริงด้วย `--preview` ขณะชี้การเชื่อมต่อไปที่ปลายทางที่เข้าไม่ถึง ปฏิเสธ JSON ที่ถูกแก้ นำเข้า 90 ชื่อและ 3 หมายเหตุในฐานทดสอบแยก และข้ามเมื่อรันซ้ำด้วยชุดเดิม
- ตรวจเบราว์เซอร์เดสก์ท็อปและจอกว้าง 390 พิกเซลบน `3afbd6c` ที่ `http://127.0.0.1:3102` ใช้ Docker PostgreSQL พอร์ต `5551` ฐาน `lthai_color_chart_web_qa` เทียบชื่อ ลำดับ และหมายเหตุครบ 90 รายการ ลองค้นไทยและอังกฤษ เพิ่มและแก้ชื่อ อัปโหลด เปลี่ยน ปฏิเสธไฟล์ผิด และลบเฉพาะภาพ บัญชีผู้ดูเปิดภาพได้ บัญชีไม่มีสิทธิ์ชาร์ตสีไม่เห็นเมนู เมนูงานปั๊มและพนักงานเดิมยังเปิดได้
- บน `6f1bc83` รัน `npm run check` และ `npm run build` ผ่าน สร้างอิมเมจ Docker API และเว็บแล้วผ่าน healthcheck รัน `npm test` ด้วย `LTHAI_COLOR_CHART_PYTHON` และเปิด `LTHAI_HANDOFF_TEST=1` บน Docker แยก ผ่าน 97 รายการ (legacy 13, API 54, เว็บ 18, handoff 12) ไม่มีล้มหรือข้าม การแก้หน้าจอหลังลบพร้อมกันใน `1182189` ผ่าน `npm run check` และชุดเว็บ 18 รายการ
- ตรวจเว็บ Docker `1182189` คู่กับ API `6f1bc83` ผ่าน healthcheck และจำลองคำขอที่ล้มในเบราว์เซอร์ โหลดภาพย่อและภาพเต็มซ้ำได้ การลองโหลดทะเบียนใหม่หลังบันทึกชื่อหรือสร้างรายการไม่ส่งคำขอเขียนซ้ำ เมื่อรายการที่เปิดอยู่ถูกลบจากอีกหน้าจอ การโหลดใหม่ปิดรายละเอียดรายการนั้นและยังเพิ่มรายการต่อได้
- ซ้อม `pg_dump` และ `pg_restore` จากฐาน QA ไปยังฐาน `lthai_color_chart_restore_*` แยกใน Docker ตรวจ 91 รายการ (ชื่อจาก Excel 90 และรายการสังเคราะห์ 1) พร้อมภาพสังเคราะห์หนึ่งภาพ ค่าแฮชของแถวใน `public` วิวงานปั๊ม และ sequence ตรงกัน เรียกภาพ WebP จาก API ด้วยบัญชีที่มีสิทธิ์หลังคืนฐานแล้วได้ SHA-256 ตรงกับภาพเดิม
- ตรวจปุ่มยกเลิกและยืนยันลบรายการสังเคราะห์บนมือถือ หลังลบตรวจฐาน QA เหลือ 90 รายการตรงกับ Excel หมายเหตุ 3 รายการ และภาพ 0 รูป เปิดเว็บทดสอบไว้ที่ `http://127.0.0.1:3102`
- ถัดไปเมื่อตกลงเปิดใช้ ให้ตรวจชุดนำเข้ากับหน้างานและทำตาม [คู่มือเปิดใช้งานชาร์ตสี](color-chart-startup.md) รอบนี้ยังไม่ได้เปิดใช้หรือนำเข้าฐานโรงงานที่ `3001`/`5434` และยังไม่ได้ push สาขา

## งานปั๊มรุ่นแรก

- พัฒนาตามแบบที่ยืนยันจาก Excel และคำตอบใน `docs/discovery.md` แล้ว การตรวจรับใช้ข้อมูลสังเคราะห์ใน Docker แยกจากฐานใช้งาน
- ตกลงรุ่นแรกเป็นยอดปั๊ม ของเสีย และสต็อก ค่าแรงเหมาและต้นทุนดินทำภายหลัง
- ระบุประเภทกระเบื้องด้วยขนาดและประเภทดิน แดง ขาว จ้อ หรือสี เพิ่มชื่อเรียกได้
- จำนวนแผ่นคำนวณจากจำนวนไม้เต็ม × แผ่นต่อไม้ของประเภทกระเบื้อง + แผ่นเศษ แยกวันที่ปั๊มกับวันที่พบของเสีย
- ทะเบียนประเภทกระเบื้องเพิ่ม ลบ แก้ไขได้ แต่ละประเภทใช้ไม้เฉพาะและระบุจำนวนวันพัก บรีสปั๊ม รอเซ็ตตัว แล้วเข้าเตาโดยข้ามงานสี
- รับเข้าสต็อกเมื่อบันทึกยอดปั๊ม แสดงกำหนดพัก และลดสต็อกเมื่อยืนยันเบิก เก็บยอดปั๊มเกินตามจริงและให้ผู้รับผิดชอบตัดสินใจเรื่องส่วนเกิน
- ใบสั่งผลิตใช้ได้ทั้งตามออเดอร์ลูกค้าและปั๊มเก็บสต็อก หนึ่งใบรวมยอดได้หลายรายการตามผู้ปั๊มจริง ส่วนสีชุบหรือสีเคลือบระบุในขั้นตอนถัดไป
- ตัดยอดของเสียเมื่อคัดหลังเผาครบและส่งยอด ใช้ผลคัดตามงานเผาเป็นแนวทางเริ่มต้น ระบุผู้ปั๊มเมื่อมีข้อมูลตามกลับได้
- เริ่มด้วยประเภทกระเบื้อง แผ่นต่อไม้ และยอดคงเหลือที่หน้างานยืนยัน ประวัติผลิตย้อนหลังรอข้อมูลเพิ่ม
- ผู้ใช้ยืนยันแบบ `docs/superpowers/specs/2026-11-11-pressing-design.md` แล้ว เหตุผลที่เลือกอยู่ที่ `docs/adr/0002-pressing-traceability.md`
- แผนพัฒนาและวิธีตรวจรับอยู่ที่ `docs/superpowers/plans/2026-11-11-pressing.md` โค้ดอยู่ใน `apps/api/src/pressing/` และ `apps/web/src/components/pressing/` เชื่อมกับสิทธิ์และเมนูเดิม
- รัน `npm test` เปิด Docker handoff integration บนฐานทดสอบแยก ผ่าน 76 รายการ ไม่มีข้าม `npm run check` และ build ผ่าน ตรวจการสร้างประเภทและใบสั่งบนเดสก์ท็อป ลงยอดและเบิกบนจอมือถือ ตรวจสิทธิ์บัญชีดูอย่างเดียว และกู้คืนข้อมูลสังเคราะห์แล้วเทียบตาราง วิวงานปั๊ม และ sequence ตรงกัน
- ตรวจกรณีเน็ตหลุดด้วย Chromium ว่าการปฏิเสธปิดหน้าต่างยังเก็บคำขอเดิม และการกดลองส่งอีกครั้งใช้ข้อมูลและรหัสเดิม
- ถัดไปคือเปิดใช้จากสาขางานปั๊มตามกระบวนการของโครงการและตรวจยอดจริงตาม [คู่มือเปิดใช้งานและลงยอดตั้งต้น](pressing-startup.md) ยอดที่ยังจับคู่ประเภทไม่ได้หรือยังผูกออเดอร์ให้พักไว้ก่อน ยอดตั้งต้นที่รับได้จะเข้าสต็อกทั่วไป

รายละเอียดงานส่งต่อและผลทดสอบด้านล่างเป็นบันทึกจากรอบ 10 พฤศจิกายน 2026

## ข้อสรุปล่าสุด

- ทำงานสลับ Windows สองเครื่อง ใช้ Codex และ Docker ทั้งสองฝั่ง ทำทีละเครื่อง
- Git ส่งโค้ด เอกสาร และ skills; OneDrive ส่งชุดสำรองฐาน Docker และไฟล์ต้นทาง
- ผู้ใช้ยืนยันฐาน Docker พอร์ต 5434 เป็นฐานตั้งต้น; เว็บพอร์ต 3001
- ตรวจเมื่อ 10 พ.ย. 2026 เวลา 15:13 น. พบ Docker เก็บ native ครบ และมีพนักงาน/ประวัติเพิ่มอย่างละ 1 รายการ ข้อมูล native พอร์ต 5433 เป็นคนละชุด
- รับข้อมูลโดยสำรองปลายทางก่อนแทนที่ และหยุดเมื่อพบงานที่ยังไม่ได้ส่ง

## งานในรอบนี้

- เพิ่ม CLI ส่ง/รับ/ตรวจสถานะ/เตรียมฐานเครื่องใหม่ ใน `scripts/handoff/`
- เพิ่มการตรวจ checksum, Git commit, ลำดับชุดส่งงาน, baseline ข้อมูลและไฟล์ส่วนตัว
- เพิ่ม `AGENTS.md` และ skills ที่ใช้กับงานนี้ใน `.agents/skills/`
- ขั้นตอนใช้งาน: `docs/cross-machine-guide.md`; แบบ: `docs/cross-machine-workflow-design.md`; แผน: `docs/superpowers/plans/2026-11-10-cross-machine-handoff.md`

## การตรวจสอบและข้อจำกัด

- focused tests ตรวจความครบถ้วนของชุดข้อมูล การเลือกไฟล์ และการหยุดรับงานเมื่อ baseline เปลี่ยน
- ทดสอบ Docker dump/restore ด้วยข้อมูลสังเคราะห์ในฐานแยก รวมความตรงกันของข้อมูล/sequence และ rollback เมื่อไฟล์เสียหาย
- ทดสอบส่งและรับจริงระหว่างโฟลเดอร์จำลองสองเครื่องกับฐานทดสอบแยก และหยุดเมื่อข้อมูล/ไฟล์ปลายทางยังไม่ได้ส่ง
- รอบสุดท้ายรัน `LTHAI_HANDOFF_TEST=1 npm test`: ผ่านครบ 42 tests รวม integration; `npm run check` ผ่าน และผู้ตรวจอิสระไม่พบ P1/P2 ค้าง
- ทดสอบซ้ำแล้วว่าการกดส่งซ้ำไม่เปลี่ยนลำดับชุดงาน รับเสร็จแต่เปิดแอปไม่ผ่านลองใหม่ได้ และ rollback กลับฐาน/ไฟล์เดิมเมื่อข้อมูลไม่ตรง
- ยังไม่ได้ทดสอบเครื่องที่บ้านหรือยืนยันการอัปโหลด OneDrive ชุดส่งงานจริงสร้างหลัง commit/push รอบนี้ โดยดู commit และรหัสชุดจาก manifest.json

## งานค้างและสิ่งที่ต้องทำต่อ

1. รอบนี้เก็บงานบน branch `codex/cross-machine-handoff` รวมการแก้ `apps/web/src/app/globals.css` ที่มีอยู่ก่อนเริ่มงาน โดยไม่ได้แก้เนื้อหานั้นเพิ่ม
2. หลังสร้างชุดส่งงานด้วย `npm run handoff:send -- --context-ready` รอ OneDrive ส่งครบก่อนปิดเครื่อง เว็บ/API จะหยุดเพื่อส่งต่อให้เครื่องที่บ้าน
3. ที่บ้าน clone/switch ไป branch เดียวกันและ commit ตรงกับชุดส่งงาน จากนั้นทำ bootstrap/receive ตามคู่มือ
4. หากมีฐาน Docker เดิมที่บ้าน ให้ตรวจเทียบก่อนรับงาน ระบบจะหยุดเมื่อพบฐานที่มีข้อมูลแต่ยังไม่มี baseline

อัปเดตไฟล์นี้ก่อน commit/push ส่งงานทุกครั้ง เพื่อให้ AI ในแชตใหม่รับช่วงได้โดยไม่ต้องให้ผู้ใช้อธิบายซ้ำ
