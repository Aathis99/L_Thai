# สถานะงานล่าสุด

อัปเดต: 10 พฤศจิกายน 2026

## เป้าหมาย

ระบบโรงงานกระเบื้องภาษาไทย ระยะปัจจุบันมีข้อมูลพนักงาน บัญชี บทบาท สิทธิ์ และประวัติการเปลี่ยนแปลง ใช้ Next.js/React/Tailwind, Express/TypeScript และ PostgreSQL

## ข้อสรุปล่าสุด

- ทำงานสลับ Windows สองเครื่อง ใช้ Codex และ Docker ทั้งสองฝั่ง ทำทีละเครื่อง
- Git ส่งโค้ด เอกสาร และ skills; OneDrive ส่งชุดสำรองฐาน Docker และไฟล์ต้นทาง
- ผู้ใช้ยืนยันฐาน Docker พอร์ต 5434 เป็นฐานตั้งต้น; เว็บพอร์ต 3001
- ตรวจเมื่อ 10 พ.ย. 2026 เวลา 15:13 น. พบ Docker เก็บ native ครบ และมีพนักงาน/ประวัติเพิ่มอย่างละ 1 รายการ ข้อมูล native พอร์ต 5433 เป็นคนละชุด
- รับข้อมูลโดยสำรองปลายทางก่อนแทนที่ และหยุดเมื่อพบงานที่ยังไม่ได้ส่ง

## งานในรอบนี้

- เพิ่ม CLI ส่ง/รับ/ตรวจสถานะ/เตรียมฐานเครื่องใหม่ ใน `scripts/handoff/`
- เพิ่มการตรวจ checksum, Git commit, ลำดับชุดส่งงาน, baseline ข้อมูลและไฟล์ส่วนตัว
- เพิ่ม `AGENTS.md` และ skills ที่ใช้กับงานนี้ใน `.agents/skills/`
- ขั้นตอนใช้งาน: `docs/cross-machine-guide.md`; แบบ: `docs/cross-machine-workflow-design.md`; แผน: `docs/superpowers/plans/2026-11-10-cross-machine-handoff.md`

## การตรวจสอบและข้อจำกัด

- focused tests ตรวจความครบถ้วนของชุดข้อมูล การเลือกไฟล์ และการหยุดรับงานเมื่อ baseline เปลี่ยน
- ทดสอบ Docker dump/restore ด้วยข้อมูลสังเคราะห์ในฐานแยก รวมความตรงกันของข้อมูล/sequence และ rollback เมื่อไฟล์เสียหาย
- ทดสอบส่งและรับจริงระหว่างโฟลเดอร์จำลองสองเครื่องกับฐานทดสอบแยก และหยุดเมื่อข้อมูล/ไฟล์ปลายทางยังไม่ได้ส่ง
- รอบสุดท้ายรัน `LTHAI_HANDOFF_TEST=1 npm test`: ผ่านครบ 42 tests รวม integration; `npm run check` ผ่าน และผู้ตรวจอิสระไม่พบ P1/P2 ค้าง
- ทดสอบซ้ำแล้วว่าการกดส่งซ้ำไม่เปลี่ยนลำดับชุดงาน รับเสร็จแต่เปิดแอปไม่ผ่านลองใหม่ได้ และ rollback กลับฐาน/ไฟล์เดิมเมื่อข้อมูลไม่ตรง
- ยังไม่ได้ทดสอบเครื่องที่บ้านหรือยืนยันการอัปโหลด OneDrive ชุดส่งงานจริงสร้างหลัง commit/push รอบนี้ โดยดู commit และรหัสชุดจาก manifest.json

## งานค้างและสิ่งที่ต้องทำต่อ

1. รอบนี้เก็บงานบน branch `codex/cross-machine-handoff` รวมการแก้ `apps/web/src/app/globals.css` ที่มีอยู่ก่อนเริ่มงาน โดยไม่ได้แก้เนื้อหานั้นเพิ่ม
2. หลังสร้างชุดส่งงานด้วย `npm run handoff:send -- --context-ready` รอ OneDrive ส่งครบก่อนปิดเครื่อง เว็บ/API จะหยุดเพื่อส่งต่อให้เครื่องที่บ้าน
3. ที่บ้าน clone/switch ไป branch เดียวกันและ commit ตรงกับชุดส่งงาน จากนั้นทำ bootstrap/receive ตามคู่มือ
4. หากมีฐาน Docker เดิมที่บ้าน ให้ตรวจเทียบก่อนรับงาน ระบบจะหยุดเมื่อพบฐานที่มีข้อมูลแต่ยังไม่มี baseline

อัปเดตไฟล์นี้ก่อน commit/push ส่งงานทุกครั้ง เพื่อให้ AI ในแชตใหม่รับช่วงได้โดยไม่ต้องให้ผู้ใช้อธิบายซ้ำ
