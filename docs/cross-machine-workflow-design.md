# ทำงานสลับเครื่องผ่าน Git, OneDrive และ Docker

วันที่: 2026-11-10
สถานะ: ผู้ใช้ยืนยันแบบและเลือก Docker เป็นฐานตั้งต้นแล้ว เริ่มพัฒนาระบบรับส่งตามแผน แต่ยังไม่ได้ย้ายฐานใช้งานจริง

## เป้าหมายและข้อกำหนดที่ยืนยันแล้ว

เปิดโปรเจกต์บน Windows อีกเครื่องแล้วทำงานต่อได้ โดย AI อ่านบริบทงานจากไฟล์ในโปรเจกต์ ไม่ต้องให้ผู้ใช้อธิบายความคืบหน้าใหม่ ทั้งสองเครื่องเป็นเครื่องส่วนตัว ใช้ Codex และมี Docker/PostgreSQL ใช้งานทีละเครื่องและส่งงานก่อนเปลี่ยนเครื่อง

ข้อมูลในแอป ไฟล์ต้นทาง และ skills ที่จำเป็นต้องตามไปด้วย ผู้ใช้เลือก Git สำหรับโค้ด/เอกสาร, OneDrive สำหรับชุดข้อมูล และ Docker เป็นระบบหลักทั้งสองเครื่อง เมื่อนำข้อมูลเข้าให้สำรองฐานปลายทางก่อนแทนที่ และหยุดหากพบงานปลายทางที่ยังไม่ได้ส่ง

## ทางเลือกที่หารือ

- Git อย่างเดียวส่งโค้ดและเอกสารได้ แต่ไม่ครอบคลุมฐานข้อมูลและไฟล์ที่ถูก ignore จึงไม่ครบเป้าหมาย
- Git ร่วมกับชุดข้อมูลผ่าน USB ทำงานได้ แต่ผู้ใช้เลือก OneDrive เพื่อรับส่งชุดข้อมูลแทนการพกสื่อ
- แบบที่เลือก: Git + ชุดข้อมูลผ่าน OneDrive + Docker ทั้งสองเครื่อง โดยแยกสำเนาฐานข้อมูลออกจากโค้ด

## ขั้นตอนใช้งานที่เสนอ

### ก่อนออกจากเครื่องหนึ่ง

1. ให้ Codex อัปเดตไฟล์สรุปงานล่าสุด: เป้าหมาย สิ่งที่ทำแล้ว ข้อสรุป งานค้าง ปัญหา และสิ่งที่ต้องทำต่อ พร้อมสถานะการตรวจสอบจริง
2. ตรวจการเปลี่ยนแปลงและ commit/push โค้ดกับเอกสาร สคริปต์ไม่อ้างว่าสร้างสรุปความหมายของบทสนทนาแทน AI ได้เอง
3. หยุดการเขียนข้อมูลเข้าแอปชั่วคราว สร้างไฟล์สำรอง PostgreSQL จาก Docker และรวบรวมไฟล์ต้นทางที่จำเป็นเป็นชุดส่งงาน
4. ชุดส่งงานมีรหัสชุด รหัส Git commit เครื่องต้นทาง เวลาสร้าง รายการไฟล์ และค่า checksum เพื่อให้ตรวจความครบถ้วนได้ สร้างเสร็จในเครื่องก่อนคัดลอกไป OneDrive
5. ตรวจว่า OneDrive ส่งไฟล์เสร็จก่อนปิดเครื่อง จากนั้นไม่แก้งานเพิ่มบนเครื่องต้นทางจนกว่าจะรับช่วงกลับมา

### เมื่อเริ่มอีกเครื่อง

1. ครั้งแรก clone โปรเจกต์ เตรียม Docker ค่าตั้งค่าส่วนตัว และ skills ตามคู่มือ หลังจากนั้น pull ก่อนเริ่มงาน
2. เลือกชุดส่งงานที่ต้องการ ตรวจว่าไฟล์ดาวน์โหลดครบ checksum ถูกต้อง และโค้ดตรงกับ Git commit ที่ระบุ ไม่ใช้เวลาแก้ไขไฟล์เพียงอย่างเดียวตัดสินว่าชุดใดใหม่กว่า
3. ตรวจงานที่ยังไม่ได้ส่ง ทั้ง Git และสถานะข้อมูลเทียบกับฐานรับส่งครั้งก่อน หากไม่แน่ใจให้หยุดโดยไม่เขียนทับ ครั้งแรกต้องตรวจฐานปลายทางที่มีอยู่ก่อน
4. สำรองฐานปลายทางและเก็บไฟล์เดิมที่จำเป็นก่อนนำเข้า หยุดแอปที่เขียนฐานระหว่างนำเข้า หากนำเข้าล้มเหลวต้องไม่รายงานว่ารับงานสำเร็จ
5. ตรวจโครงสร้างและจำนวนรายการตามชุดส่งงาน เปิดแอปและตรวจ health จากนั้นให้ Codex อ่านบริบทก่อนทำงานต่อ

## การจัดเก็บ

- โปรเจกต์ทำงานอยู่ในโฟลเดอร์ปกติ เช่น D:\LThai; OneDrive ใช้เก็บชุดส่งงานที่สร้างเสร็จแล้ว
- Git เก็บโค้ด เอกสาร แนวทางอ่านบริบท และ skills ที่เลือกและตรวจแล้วว่าจำเป็นต่อโปรเจกต์
- ชุดข้อมูลส่วนตัวเก็บไฟล์สำรองฐานและไฟล์ต้นทางตามรายการที่ระบุชัด ไม่คัดลอก data/ ทั้งหมด ซึ่งรวมฐาน native ที่รันอยู่ บันทึกเก่า และไฟล์สำรองสะสม
- ค่าลับที่จำเป็นต่อ Docker ตั้งผ่านช่องทางส่วนตัว ไม่ขึ้น Git; ค่าที่ผูกกับเครื่องต้องปรับตามปลายทาง ไม่คัดลอก config ของ Codex ทั้งโฟลเดอร์
- ติดตั้ง/ลงชื่อเข้าใช้ Codex และบริการที่ต้องใช้แยกบนแต่ละเครื่อง ไฟล์บริบทช่วยรับช่วงงาน แต่ไม่ได้หมายถึงย้ายทุกข้อความในแชตหรือสถานะภายในแอป
- ไม่ย้าย Docker volumes หรือโฟลเดอร์ PostgreSQL ที่กำลังรันผ่าน OneDrive ใช้ logical dump และ restore แทน

## เกณฑ์ตรวจรับก่อนใช้งานจริง

- ทดลองส่งและรับลงฐานแยกก่อนนำเข้าฐานใช้งานจริง และตรวจว่าข้อมูลครบ
- ทดสอบกรณีไฟล์ไม่ครบ checksum ไม่ตรง Git commit ไม่ตรง และมีงานปลายทางที่ยังไม่ได้ส่ง ต้องไม่เขียนทับ
- ตรวจว่าข้อมูลสำรองปลายทางกู้คืนได้ และความล้มเหลวไม่ถูกแสดงเป็นสำเร็จ
- ทดลองเปิดจากเครื่องที่บ้าน ให้ Codex อธิบายงานล่าสุดจากเอกสารและเปิดแอปพร้อมข้อมูลตรงกับชุดส่งงานได้

คำสั่งรับส่งถูกสร้างแล้วและทดสอบ dump/restore กับ workflow ในฐาน Docker ทดสอบแยก ข้อจำกัดปัจจุบัน: ยังไม่ได้ตรวจเครื่องที่บ้านหรือทดสอบการส่ง OneDrive จริง และยังไม่สร้างชุดส่งงานจริงจนกว่าจะ commit/push งานครบ
