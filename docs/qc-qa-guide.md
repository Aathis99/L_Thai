# ตรวจรับงานใบ QC

สถานะ 25 พฤศจิกายน 2026: โค้ดและเว็บ QA พร้อมให้ตรวจรับ ยังไม่นำขึ้นฐานหลัก

## เปิดใช้งาน QA

- เปิด http://qc.localhost:3160 หรือ http://localhost:3160 แล้วเลือก **ตรวจสอบคุณภาพ(QC)** จะเข้าใบ QC โดยตรง แนะนำ qc.localhost เพื่อแยก cookie จากระบบหลัก
- หลังถอดรูปแบบเก่า ใช้งานฝึก120แผ่นตาม [วิธีทดสอบแบบง่าย](qc-simple-test.md) เมนูงานเดิมและคิวกรอกQCรายครั้งถูกถอดแล้ว ข้อมูลเก่าถูกล้างเฉพาะQAหลังสำรอง
- บัญชีทดสอบ `qc-review` รหัสผ่านเก็บใน `.qa/qc-documents/review-account.txt` บนเครื่องนี้ ไม่ใช่บัญชีใช้งานจริงและไม่เก็บรหัสผ่านใน Git
- QA ใช้ Docker project `lthai-qc-qa` เว็บ3160/API4160 ฐานและ role `lthai_qc_documents_qa` แยกจาก `lthai` ระบบหลัก3001ยังเป็นรุ่นเดิม

## ตัวอย่างที่เตรียมไว้

ใบ `QC-2569-000001` รอบเผา#13 รวมออเดอร์ `QA-QC-OD-001/002` ใบสั่งผลิต#10/#11 รายการเข้าเตา#14/#15 รวม240แผ่น ตัวอย่างนี้เป็นข้อมูลทดสอบทั้งหมด ไม่ย้ายขึ้นหลักโดยอัตโนมัติ

ตรวจผ่านหน้าเว็บแล้ว:

1. บันทึกร่าง60แผ่น ยอดยืนยันยัง0 และยอดรอคัด240
2. ยืนยันครั้งแรก60 เหลือรอคัด180 และยอดของออเดอร์ที่สองยัง0
3. เปิดร่างเดียวกันสองหน้าต่าง อีกหน้าต่างแก้ก่อน การส่งค่าค้างถูกปฏิเสธ โหลดล่าสุดแล้วเปิดค่าที่อีกคนแก้พร้อมข้อความแจ้ง ไม่บันทึกทับเงียบ ๆ
4. ยืนยันครบ240 ยอดแต่ละออเดอร์เป็น A+100/เสีย10/ไม่สุก5/แต้ม5 รวม A+200/เสีย20/ไม่สุก10/แต้ม10
5. ออกฉบับทางการ พิมพ์ซ้ำไม่สร้างฉบับเพิ่ม แก้หมายเหตุพร้อมเหตุผลแล้วออกฉบับแก้ไขครั้งที่1 เลข QC เดิม ฉบับเก่ายังมีหมายเหตุเดิมและถูกระบุเป็นข้อมูลก่อนแก้ไข
6. เปิดใบสั่งผลิตต้นทางได้จริง และเปิดตัวอย่างใบจดหน้างานที่มีช่องเขียน/อาการตรงกับแบบธุรการได้

## การตรวจพิมพ์ที่ยังต้องทำก่อนรับงาน

เปิดใบ → **พิมพ์ฉบับทางการซ้ำ** หรือ **พิมพ์ใบจดหน้างาน** → **พิมพ์ / บันทึก PDF** เลือก A4 แนวตั้ง ตรวจภาษาไทย ตารางอาการ ช่องเซ็น หน้าแนบ และเลขหน้า รวมกรณีชื่อยาว/หลายออเดอร์/หลายหน้า

ตรวจเนื้อหาและตัวอย่างเอกสารในเว็บแล้ว แต่ยังไม่ยืนยัน PDF ที่บันทึกจริงหรือกระดาษจริง: เครื่องมือควบคุม Brave คืนข้อผิดพลาด geometry/window bounds ระหว่างตรวจ native print จึงไม่อ้างว่าผ่านการตรวจหน้ากระดาษแล้ว รายการนี้ยังเปิดอยู่ในแผนและสถานะล่าสุด

- logs, baseline hashes, credentials และ manifest อยู่ `.qa/qc-documents/` นอก Git; สำรองหลักและ SHA256 อยู่ตาม `docs/CURRENT.md`

## ก่อนนำขึ้นหลัก

ให้ผู้ใช้ตรวจรับโมดูลและยืนยันข้อมูลที่จะเก็บ โดยปกติตัวอย่าง QA ไม่ใช่ข้อมูลผลิตจริง จากนั้นสำรองหลักสดอีกครั้ง ใช้โค้ด/การเปลี่ยนแปลงแบบเพิ่มและข้อมูลที่อนุมัติเท่านั้น ไม่กู้ QA ทั้งฐานทับหลัก ตรวจการใช้งานหลักแล้วจึงถอด QA และเก็บ backup ตาม AGENTS.md
