# Employee Access Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task. The user explicitly requested implementation of the narrowed access module now.

**Goal:** A usable Thai employee and access management app.
**Architecture:** Local HTTP server, SQLite storage, cookie sessions and server-side authorization; browser frontend with no build pipeline.
**Tech Stack:** Node.js 26 built-ins, HTML/CSS/JavaScript.
**Spec:** ../specs/2026-11-09-access-design.md

## Global Constraints
- Bind to 127.0.0.1. No default administrator password or example employee records.
- Separate employee positions from access roles; leave production workflows and Excel mapping pending.
- Database and logs excluded from source; preserve existing discovery notes.

## Review Focus
- A disabled user must lose access immediately.
- The last administrator cannot be deleted or demoted.
- User-controlled names must render as text and never execute HTML.
- Duplicate employee codes/usernames and in-use roles/positions must give useful errors.
- Permission changes must affect existing sessions without re-login.
