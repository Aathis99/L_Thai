# Kiln workflow production rollout

> **For agentic workers:** Use executing-plans inline. Follow test-driven-development and verification-before-completion. User authorized production deployment and explicitly chose to discard synthetic QA records on 2026-11-20.

**Goal:** Run the accepted kiln workspace on Docker/main with real source reservations, grade-separated stock and an empty new workflow, retaining existing production data.
**Architecture:** Reuse the tested transition model. Store versioned workflow/audit in dedicated production tables; maintain relational source debits and allocation projections in the same transaction and existing factory advisory lock. Existing source/stock/order queries include these projections. QA demo endpoints retain their exact QA gate and never become the production interface.
**Tech Stack:** Existing Express/PostgreSQL/React/Next.js. No new dependencies.
**Spec:** docs/superpowers/specs/2026-11-19-kiln-workflow-design.md, plus user authorization above.

## Constraints
- Fresh main backup -> separate restored `lthai_kiln_live_qa`, verify exact database/user before tests/migrations.
- Production temperatures/grade policies start unset except previously confirmed existing ranges. No synthetic items, accounts, passwords, quantities or events copied.
- Preserve existing employees, orders, inventory and concurrent main changes. Never restore QA over main.
- All live reservations debit real issue/batch quantities; upstream corrections/returns and legacy loading cannot spend reserved pieces.
- Existing legacy records remain readable. New stock receipts appear in finished stock with grade; corrections remain audited.
- Main rollout is authorized. Back up main and both QA databases again immediately before switching services, then verify main read-only and remove only module QA processes/databases after success.

## Review focus
- Source readiness changes between opening a form and saving; stale revision and shared lock must prevent overdraft.
- Partial source correction/cancellation releases exactly the original issue/batch debit; refires consume no fresh source twice.
- Legacy kiln operations and upstream returns/corrections respect live holds, including OS/breeze paths.
- Customer demand already allocated by legacy QC cannot be allocated again; stock grades never coalesce.
- Production API refuses demo/imported synthetic state and quantity overrides; empty migration is idempotent and preserves existing data.

## Decisions
- User chose fresh start; no QA data selected for production.
- The shared model remains the validated write boundary; relational debits/projections make existing inventory queries honor that boundary. Every projection is updated with the model/audit in one transaction, never by a background sync.
- Physical input origins are assigned to each reservation in ready-date/id order and retained during corrections; decreases release from the end of that reservation only.
- Missing factory criteria block preparation/allocation while allowing planning; no factory temperature/grade is guessed.
