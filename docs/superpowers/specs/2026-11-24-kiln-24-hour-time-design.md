# เวลา 24 ชั่วโมงสำหรับรอบเผาและไฟ

ผู้ใช้ยืนยัน Q1/Q2 วันที่ 24 พฤศจิกายน 2026

## ขอบเขตที่ยืนยัน

ช่องเวลาสำหรับเข้าเผา/จุดไฟ บันทึกไฟ ปิดไฟ นำเบอร์ออก และเอาของลงเสร็จ ใช้วันที่เดิมและชั่วโมง 00–23 กับนาที 00–59 โดยไม่มี AM/PM ส่วน QC และการจัดสรรยังใช้ช่องวันเวลาเดิม

## แนวทาง

เลือกแยกช่องวันที่ ชั่วโมง และนาที เพราะ native datetime-local ให้เบราว์เซอร์กำหนดหน้าตาเวลาและอาจแสดง AM/PM การแยกช่องทำให้บังคับการกรอก 24 ชั่วโมงได้แน่นอนโดยใช้ฟอร์มเดิมและไม่เพิ่มไลบรารีปฏิทิน

ผู้ใช้ยืนยันปรับวิธีเลือกเพิ่มเติมวันที่ 24 พฤศจิกายน 2026: ใช้ Dropdown ชั่วโมง00–23และนาที00–59 เลือกได้ครบทุกนาทีไม่ปัดเศษ พร้อมปุ่ม “ใช้เวลาปัจจุบัน” เติมทั้งวันที่และเวลาของไทย ณ ตอนกด เพื่อรองรับข้ามเที่ยงคืน ปุ่มนี้ไม่ส่งคำสั่งบันทึก ผู้ใช้ยังตรวจทานและกดบันทึกด้วยตนเอง เลือกแนวทางนี้เพื่อใช้ได้ทั้งเมาส์และจอสัมผัส โดยไม่ต้องใช้วงล้อหรือหน้าปัดนาฬิกา

ใช้ FireTimeInput/fireAtField เฉพาะห้าเหตุการณ์ข้างต้น โดยคง TimeInput/atField สำหรับงานอื่น ค่าเริ่มต้นเป็นเวลาปัจจุบันของไทย ตรวจวันที่ ชั่วโมง และนาทีก่อนส่ง รูปแบบส่ง API คงเป็น ISO ปี ค.ศ. เช่น `2026-11-24T13:30:00+07:00` รายการเก่าแสดงด้วย Asia/Bangkok ตามเดิม ไม่บวกเวลาอีกเจ็ดชั่วโมง

ไม่มี migration หรือการแปลงข้อมูลย้อนหลัง โครงสร้างฐาน/API และกติกาเรียงลำดับเหตุการณ์คงเดิม ขอบเขตนี้เป็นการเปลี่ยนวิธีกรอกเวลาบนเว็บ ไม่เปลี่ยนปีปฏิทินหรือเพิ่มการแก้เวลาในประวัติ

## การตรวจ

ตรวจ payload 13:30, 23:59 และ 00:05 ของวันถัดไป; ปฏิเสธช่องว่าง เวลาเกินช่วง เศษชั่วโมง และวันที่ไม่มีจริง; ยืนยัน payload เดิมของ QC/จัดสรร พร้อมตรวจ TypeScript ชุดเว็บ และ Docker web build การตรวจหน้าจอจริงเปิดฟอร์มโดยไม่บันทึกงานทดสอบในฐานหลัก
