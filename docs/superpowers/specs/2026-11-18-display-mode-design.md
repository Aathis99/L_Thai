# โหมดสว่างและโหมดมืดสำหรับ LThai

สถานะ ผู้ใช้ตรวจรับและเปิดใช้งานบน lthai-docker พอร์ต 3001 เมื่อ 18 พฤศจิกายน 2026

## สิ่งที่ผู้ใช้ยืนยัน

- เปิดเว็บครั้งแรกด้วยโหมดสว่าง
- จำโหมดที่เลือกไว้ในเบราว์เซอร์
- โหมดมืดใช้สีเข้มที่อ่านสบายสำหรับการใช้งานต่อเนื่อง โดยเลือกโทนสีได้อิสระจากสีเขียวของโรงงาน
- ปุ่มขวาบนแสดงพระอาทิตย์เมื่ออยู่ในโหมดสว่าง และพระจันทร์เมื่ออยู่ในโหมดมืด กดเพื่อสลับโหมด
- ใช้ CSS กลางร่วมกับ Tailwind ให้ครอบคลุมทุกหน้าและทุกโมดูล

## แบบที่เสนอ

ปุ่มไอคอนเส้นขนาดประมาณ 20px อยู่ขวาสุดของ navbar พื้นที่กดอย่างน้อย 40 × 40px มีคำอธิบายภาษาไทยสำหรับโปรแกรมอ่านหน้าจอและเมื่อชี้เมาส์ ใช้คีย์บอร์ดกดได้ หน้าเข้าสู่ระบบและตั้งผู้ดูแลครั้งแรกมีปุ่มเดียวกันที่มุมขวาบนของหน้า รองรับจอมือถือ

โหมดมืดใช้สีเทาเข้มโทนกลางตามตารางนี้ ค่าสีเป็นข้อเสนอของผู้พัฒนา

| การใช้งาน | สี |
| --- | --- |
| พื้นหลังหน้า | `#16181b` |
| การ์ด เมนู และหน้าต่างย่อย | `#202327` |
| พื้นที่เน้นและแถวเมื่อชี้เมาส์ | `#2a2e34` |
| ช่องกรอก | `#191c20` |
| เส้นแบ่ง | `#414750` |
| ข้อความหลัก | `#e4e7eb` |
| ข้อความรอง | `#aeb6c2` |
| ปุ่มหลักและจุดเน้น | `#8ab4f8` พร้อมข้อความเข้ม |

สีสถานะแยกความหมายด้วยเขียว เหลือง และแดงที่อ่านได้บนพื้นเข้ม ปุ่มและช่องกรอกมีกรอบเมื่อโฟกัส ภาพชาร์ตสีแสดงสีต้นฉบับ พื้นที่รอบภาพปรับตามโหมด

## แนวทางพัฒนา

ใช้ตัวแปรสีตามหน้าที่ใน CSS กลางและกำหนดค่าแต่ละโหมดบน `html[data-theme]` เชื่อมกับ Tailwind v4 ผ่าน theme tokens และ dark variant ให้หน้าใหม่ใช้โครงเดียวกันได้ ตรวจและเปลี่ยนสีที่ระบุโดยตรงใน globals.css ให้ครอบคลุมหน้าเข้าสู่ระบบ เมนู ตาราง ฟอร์ม dialog ป้ายสถานะ งานผลิต สต็อก และชาร์ตสี

เก็บค่า `light` หรือ `dark` ใน localStorage โดยเริ่มต้น light หากยังไม่มีค่าหรือค่าที่เก็บใช้ไม่ได้ โหลดค่าก่อนแสดงหน้าเพื่อป้องกันหน้าเว็บสว่างวาบเมื่อเปิดโหมดมืด และตั้ง color-scheme ให้ช่องกรอกของเบราว์เซอร์สัมพันธ์กับโหมด เมื่อ storage ใช้งานไม่ได้ยังสลับโหมดในหน้าปัจจุบันได้ เมื่อเปลี่ยนในอีกแท็บให้แท็บที่เปิดอยู่ตามค่าล่าสุด

การเลือกเป็นของเบราว์เซอร์นั้น และคงอยู่หลังออกจากระบบ ใช้ฟอนต์และขนาดตัวอักษรเดิม

### ทางเลือกที่พิจารณา

- CSS tokens กลางร่วมกับ Tailwind เป็นแนวทางที่เสนอ เพราะควบคุมสีของ component เดิมและหน้าใหม่จากจุดเดียวได้
- เติม dark utility ทุกจุดใน JSX ต้องดูแลซ้ำหลายหน้าและยังต้องปรับ component CSS เดิม
- เพิ่ม theme library มีประโยชน์เมื่อมีหลายธีมหรือเงื่อนไขซับซ้อน ขอบเขตสองโหมดนี้ใช้สถานะส่วนกลางขนาดเล็กได้

## การตรวจรับและส่งมอบ

ตรวจการเปิดครั้งแรก การสลับและจำค่า การรีเฟรช การออกและเข้าใหม่ การเปลี่ยนหลายแท็บ การใช้คีย์บอร์ด และกรณี storage ใช้งานไม่ได้ ตรวจหน้าระบบและหน้าต่างย่อยบนคอมและมือถือ โดยเทียบความชัดเจนของข้อความ สีสถานะ และสีภาพจริง พร้อมรัน typecheck การ build และชุดทดสอบเว็บที่เกี่ยวข้อง

เตรียมเว็บทดสอบบนฐาน QA ที่กู้จากสำรองใหม่ของ Docker ตาม AGENTS.md และตรวจปลายทางก่อนเขียนข้อมูล ให้ผู้ใช้ตรวจรับโมดูลก่อนนำขึ้นชุดหลักตามขั้นตอนเดิม อัปเดต docs/CURRENT.md ตามสถานะจริง

การเปลี่ยนโหมดเป็นแนวคิด UI ทั่วไป จึงบันทึกในแบบนี้ ส่วน GLOSSARY.md ใช้คำศัพท์เฉพาะงานโรงงาน การเลือกวิธีนี้ย้อนเปลี่ยนได้ง่าย จึงบันทึกเหตุผลไว้ในแบบโดยใช้เกณฑ์ ADR ของ domain-modeling
