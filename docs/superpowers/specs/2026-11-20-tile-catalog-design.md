## ทางเลือกและข้อยืนยัน

- ทางเลือก A แสดงสินค้าเดียวกันสี่รายการตามดิน ใกล้ระบบเดิมแต่รายละเอียดสินค้าซ้ำและทะเบียนยาว
- ทางเลือก B แสดงสินค้าแต่ละแบบครั้งเดียว แล้วเลือกดินในใบสั่งปั๊ม ผู้ใช้เลือก B ใน Q4 ข้อมูลผลิตภายในยังแยกตามดินได้เพื่อรักษาสต็อกและประวัติ
- กระเบื้องทุกแบบผลิตได้จากดินแดง ขาว ศิลาแลง และสี ศิลาแลงเป็นชื่อใหม่ของจ้อ
- Q2–Q3 เก็บครบทุกแถวและทุกรหัส ไม่รวมรายการตามรหัส ชื่อ หรือขนาดเพียงอย่างเดียว
- Q5 ตั้งแผ่นต่อไม้ วันพัก และแผ่นต่อ ตร.ม. แยกตามดินได้
- Q6 สินค้าลายวาดต่างรหัสใช้แบบดินปั๊มร่วมกันได้เมื่อหน้างานยืนยันว่าเป็นแผ่นพื้นเดียวกัน
- Q7 ติดตาข่ายหลังได้กระเบื้องแล้ว ทำเมื่อมีออเดอร์ งานปั๊มนับแผ่นย่อย
- Q8 ค้นดูรายการที่ข้อมูลผลิตยังไม่ครบได้ แต่ยังเปิดผลิตด้วยข้อมูลที่ไม่ครบไม่ได้
- Q9 ดินสีต้องระบุสีที่ผสมและแยกสต็อกตามสีดิน
- Q10 ต้องให้ใบสั่งรู้ว่าติดตาข่ายหรือไม่ และมีเฉพาะสินค้าบางแบบที่รองรับ ไม่ใช้ข้อเสนอเดิมที่พักการเปิดใบสั่งสินค้าติดตาข่ายทั้งหมด
- Q11 ยืนยันงานติดตาข่ายต้องรอหลัง QC บันทึกเสร็จได้บางส่วน และพร้อมส่งเฉพาะยอดที่ติดเสร็จแล้ว
- Q12 ยืนยันใช้แผ่นกระเบื้องย่อยเป็นหน่วยหลักของใบสั่งและงานติดตาข่าย ไม่เพิ่มหน่วยชุดตาข่ายหรืออัตราแปลงแผ่นต่อชุดในรุ่นนี้

## ขอบเขต

รวมทะเบียนสินค้า การจับคู่แบบดินปั๊ม การตั้งค่าผลิตรายดิน การเลือกในใบสั่ง การรักษาเอกลักษณ์สินค้าต่อไปถึงงานสี เตา QC และสต็อก การนำเข้าที่รันซ้ำแล้วไม่เพิ่มรายการซ้ำ และการเปลี่ยนชื่อดินเป็นศิลาแลง

ไม่เพิ่มสูตรผสมดิน ต้นทุน ราคา ระบบขายเต็มรูปแบบ ประวัติการผลิตจากไฟล์ หรือการอนุมานค่าหน้างานจากขนาด ไม่มีจำนวนสต็อกในต้นทางนี้ จึงไม่สร้างยอดตั้งต้นจากไฟล์นี้

รวมการเปิดใบสั่งที่ระบุสินค้าติดตาข่ายเมื่อข้อมูลผลิตพร้อม โดยให้ความต้องการติดตาข่ายมาจากรายการสินค้าที่เลือก งานนี้ต้องมีออเดอร์ลูกค้า ไม่เปิดผลิตสินค้าติดตาข่ายเพื่อเก็บสต็อกโดยไม่มีออเดอร์ ส่วนแผ่นพื้นยังสั่งปั๊มเก็บได้ตามเดิม

ข้อเสนอวิธีทำตาม Q10: แยกสินค้ารุ่นติดตาข่ายกับรุ่นที่ไม่ได้ระบุตาข่ายตามต้นทาง แม้ใช้รหัสเดียวกัน และเลือกสินค้ารุ่นที่ต้องการในใบสั่ง ระบบเก็บความต้องการติดตาข่ายไว้กับใบนั้น ไม่ใช้ checkbox แยกที่เปิดให้สินค้าทุกแบบติดตาข่ายได้ เริ่มรองรับตามหกรายการในไฟล์ ผู้มีสิทธิ์เพิ่มรุ่นติดตาข่ายได้เมื่อหน้างานยืนยัน ไม่อนุมานจากขนาดเล็ก และยังไม่ระบุว่าเป็นรุ่นยอดนิยมโดยไม่มีข้อมูลยอดขาย

รวมการบันทึกติดตาข่ายเสร็จหลัง QC เป็นจำนวนแผ่นย่อย บันทึกได้บางส่วนจนกว่าจะครบออเดอร์ แยกยอดผ่าน QC ที่กันให้ออเดอร์ออกจากยอดติดตาข่ายเสร็จและยอดพร้อมส่ง ไม่เพิ่มระบบจัดแผนผังตาข่าย สูตรประกอบหลายแบบดินปั๊ม หรือการนับชุดตาข่ายในรุ่นนี้

## ความหมายและความสัมพันธ์

1. **รายการสินค้า** คือรายการที่มีรหัสและรายละเอียดตามต้นทาง หนึ่งรหัสอาจมีหลายรายการที่ต่างความหนาหรือการติดตาข่าย ใช้ id ภายในแยกแต่ละรายการ สินค้าต่างรหัสยังคงแยกกันแม้ข้อความเหมือนกัน
2. **แบบดินปั๊ม** คือรูปแบบของแผ่นก่อนทำสี/วาดลาย/ติดตาข่าย ต้องแยกเมื่อรูปร่าง ความหนา ลายนูน หรือรายละเอียดที่ขึ้นรูปต่างกัน ขนาดเท่ากันไม่เพียงพอให้รวมแบบ
3. **ประเภทกระเบื้องสำหรับผลิต** คือแบบดินปั๊มพร้อมชนิดดิน และชื่อสีดินเมื่อเป็นดินสี มีค่าผลิตและตัวอ้างอิงสำหรับสต็อกของตนเอง สินค้าที่ใช้แผ่นพื้นร่วมกันอ้างถึงประเภทผลิตเดียวกันได้

รายการสินค้ามีแบบดินปั๊มที่ตรวจยืนยันแล้วหนึ่งแบบสำหรับรุ่นนี้ หากสินค้าประกอบต้องใช้หลายแบบ ให้เก็บทะเบียนไว้แต่ยังไม่เปิดผลิตจนออกแบบส่วนประกอบ มีดินได้ทั้งสี่ประเภทแต่ไม่สร้างค่าผลิตสมมติครบสี่แบบให้อัตโนมัติ

ดินสีใช้ชื่อสีดินเป็นส่วนหนึ่งของเอกลักษณ์ประเภทผลิต ชื่อสีดินเป็นชื่อส่วนผสมที่หน้างานยืนยัน ไม่ใช่ชื่อสีเคลือบ และไม่เก็บสูตรหรือสัดส่วนผสมในรุ่นนี้ บังคับระบุเมื่อเลือกดินสี ใช้ประเภทผลิตที่มี id แยกกันสำหรับแต่ละสีดิน การแก้ชื่อแสดงภายหลังไม่ทำให้ดินคนละสีรวมสต็อกกัน

## ข้อมูลสินค้าและขนาด

เก็บรหัส ชื่อ รูปทรง ขนาดมิติแรก มิติที่สองเมื่อมี หน่วย ความหนา การติดตาข่าย และรายละเอียดแบบ/ลาย แยกจากค่าผลิตรายดิน คำบรรยายเดิมและตำแหน่งต้นทางใช้ตรวจย้อนกลับในหลักฐานนำเข้าส่วนตัว

- ช่องว่างคือไม่ระบุ ไม่ใช่ศูนย์ ความหนามีค่าเฉพาะสามรายการในไฟล์ และไม่ได้ยืนยันความหนาปกติของรายการอื่น
- ต้นทางใช้หน่วยนิ้วและความหนามิลลิเมตร รองรับทศนิยม ไม่แปลงหรือปัดขนาดระหว่างนำเข้า
- 50 รายการมีมิติเดียว ต้องรองรับโดยไม่เติมมิติที่สองเท่ามิติแรก วงกลมใช้เส้นผ่านศูนย์กลางเมื่อมีหลักฐาน ส่วนมิติรูปทรงอื่นที่ยังไม่ยืนยันเก็บตามต้นทางพร้อมรอตรวจ
- รูปทรงว่าง 32 รายการยังคงว่างได้ ชื่อรายละเอียดเดิมช่วยแสดงผล ห้ามเติมเป็นสี่เหลี่ยมเอง
- รูปทรงพิเศษไม่ใช้ความกว้างคูณยาวคำนวณแผ่นต่อ ตร.ม. อัตรามาจากหน้างานเท่านั้น
- รหัสซ้ำเก้ากลุ่มแตกต่างความหนาหรือตาข่าย ไม่ตั้ง unique constraint ที่รหัสอย่างเดียว และไม่ใช้ชื่อ+ขนาดเป็นคีย์ตัดซ้ำ
- รูปตัวอย่างไม่อยู่ในไฟล์ รุ่นนี้ไม่สร้างรูปหรือระบบรูปสินค้าใหม่ สามารถเพิ่มภายหลังโดยอ้าง id สินค้าเดิม

## ค่าผลิตและความพร้อม

ประเภทผลิตแต่ละชุดกำหนดจำนวนแผ่นต่อไม้เป็นจำนวนเต็มบวก วันพักเป็นจำนวนเต็มตั้งแต่ศูนย์ อัตราแผ่นต่อ ตร.ม. เป็นจำนวนบวก และปลายทางงานสีหรือเข้าเตา ต้องกรอกยืนยันค่าครบก่อนเปิดใบสั่งใหม่ ศูนย์วันพักใช้ได้เฉพาะเมื่อยืนยันจริง ไม่ใช้เป็นค่าเริ่มต้นแทนช่องว่าง

รายการค้นดูได้แม้ยังไม่มีแบบดินปั๊มหรือค่าผลิต ไม่มีอัตราผลิต ชนิดดิน หรือยอดสต็อกสมมติ ผู้จัดการกำหนดค่าตามดินจริง จึงเปิดใช้ผลิตเฉพาะประเภทนั้น ดินสีแต่ละสีมีความพร้อมของตนเอง

รายละเอียดเพื่อให้ตรวจพร้อมแบบ: ช่วงอุณหภูมิรูปแบบผูกกับประเภทผลิตตามตัวอ้างอิงเดิมได้ จึงแยกตามดิน/สีดินได้ ใช้ร่วมกับช่วงดินและสีเคลือบตามกติกางานเตาเดิม ไม่คัดลอกช่วงอุณหภูมิโดยไม่มีการยืนยัน การไม่มีช่วงอุณหภูมิยังตรวจตอนเตรียมเข้าเตาตามระบบเดิม ไม่บังคับเป็นเงื่อนไขสร้างทะเบียน

## ใบสั่งผลิตและประวัติ

เลือกสินค้าจากชื่อ รหัส และรายละเอียดที่ช่วยแยกรายการ รวมข้อความติดตาข่ายของรุ่นนั้น เลือกดินและสีดินเมื่อเกี่ยวข้อง ระบบเลือกประเภทผลิตที่เชื่อมไว้แล้ว แสดงค่าผลิตและความต้องการติดตาข่ายก่อนบันทึก สีเคลือบเลือกแยกตามเส้นทางงานสีตามเดิม หากเลือกสินค้าติดตาข่ายต้องเป็นใบสั่งตามออเดอร์ลูกค้า ไม่เปิดช่องเลือกติดตาข่ายให้สินค้าที่ไม่มีรุ่นรองรับ

รายละเอียดเพื่อให้ตรวจพร้อมแบบ: ใบสั่งใหม่บันทึกเอกลักษณ์สินค้า แบบดินปั๊ม ประเภทผลิต ชนิดดิน/สีดิน ชื่อรายละเอียดสินค้า ความต้องการติดตาข่าย และค่าผลิต ณ เวลาสร้างใบไว้ การแก้ทะเบียนภายหลังไม่เปลี่ยนชนิดดิน รหัสสินค้า ความต้องการติดตาข่าย อัตราแผ่นต่อไม้ วันพัก หรือพื้นที่ของใบที่เปิดแล้ว หากต้องเปลี่ยนงาน ให้ใช้กติกาแก้ใบที่ยังไม่ถูกใช้/ย้อนงานของระบบเดิม ไม่ย้ายยอดไปประเภทอื่นเงียบ ๆ

ใบเก่าที่มี snapshot แล้วรักษาค่านั้น ส่วนค่าที่ใบเก่ายังไม่มีให้เติมจากทะเบียนหลักปัจจุบัน ณ cutover หลังตรวจ target และเก็บหลักฐาน โดยไม่คำนวณหรือเขียนทับจำนวนแผ่น พื้นที่ วันพัก หรือวันพร้อมที่บันทึกในรายการเดิมแล้ว

## สต็อกและขั้นตอนต่อไป

ก่อนทำสี/ลาย สต็อกแยกตามประเภทผลิต ซึ่งรวมแบบดินปั๊ม ชนิดดิน และสีดิน การใช้กองร่วมต้องเป็นประเภทผลิตเดียวกันและยังผ่านกติกาการกันตามออเดอร์ การปล่อยส่วนเกิน และการเบิกเดิม ไม่เปิดให้ดึงของที่กันให้ใบอื่นเพียงเพราะแบบตรงกัน

เมื่อนำไปทำสี/ลาย รายการทำงานอ้างสินค้าและใบสั่งปลายทาง หลังตกแต่งแล้วไม่รวมกองต่างรหัสสินค้าเพียงเพราะแบบดินปั๊มหรือชื่อสีเคลือบตรงกัน งาน QC สต็อกสินค้าสำเร็จ และยอดพร้อมส่งต้องรักษาเอกลักษณ์สินค้า ประเภทผลิต สีเคลือบ และเกรด การตรวจช่วงอุณหภูมิและ catalog version ของงานเตายังคงทำงาน

ข้อมูลเดิมที่ยังไม่จับคู่รหัสสินค้าแสดงเป็นรายการเดิม ไม่เดาสินค้าจากขนาด และไม่รวมกับสินค้ารหัสใหม่อัตโนมัติ ประวัติการจัดสรรและยอดเดิมไม่ถูกย้ายเพียงเพราะเพิ่มทะเบียนสินค้า

## งานติดตาข่ายและยอดพร้อมส่ง

ใบสั่งเก็บความต้องการติดตาข่ายจากรุ่นสินค้าที่เลือก งานปั๊ม งานสี เตา และ QC ยังนับเป็นแผ่นย่อยเหมือนกันทั้งหมด ไม่ต้องแปลงเป็นชุดตาข่าย และไม่ใช้จำนวนที่ผลิตเผื่อแทนจำนวนที่ลูกค้าสั่ง

เมื่อคัด QC และจัดสรรแผ่นเกรดที่ออเดอร์ยอมรับให้ใบนั้นแล้ว แผ่นดังกล่าวเป็นยอดรอติดตาข่าย ผู้บันทึกระบุจำนวนแผ่นที่ติดเสร็จจริงในแต่ละครั้ง พร้อมรักษาแหล่งจัดสรร QC/เกรดและเอกลักษณ์สินค้า/ประเภทผลิต เก็บผู้บันทึก เวลา และประวัติรายการ

- บันทึกได้เฉพาะใบสั่งลูกค้าที่ต้องติดตาข่าย จำนวนเป็นจำนวนเต็มบวก และไม่เกินยอดจัดสรรที่ยังไม่ใช้ติดตาข่ายของใบนั้น รวมแล้วไม่เกินจำนวนลูกค้าสั่ง
- สินค้าคนละรุ่น ชนิดดิน สีดิน สีเคลือบ หรือเกรดที่ออเดอร์ไม่ยอมรับ ใช้แทนกันไม่ได้ แม้ใช้แบบดินปั๊มพื้นร่วมกัน การบันทึกระบุแหล่งจัดสรรที่ใช้จริง ไม่รวมกองด้วยขนาดเพียงอย่างเดียว
- ยอดรอติดตาข่าย = ยอดแผ่นผ่าน QC ที่จัดสรรให้ออเดอร์และยังใช้งานได้ − ยอดติดตาข่ายเสร็จสุทธิ
- งานไม่ติดตาข่ายพร้อมส่งตามยอด QC ที่กันให้ออเดอร์เดิม งานติดตาข่ายพร้อมส่งเฉพาะยอดติดเสร็จสุทธิ ห้ามนับยอดจัดสรรกับยอดติดเสร็จบวกกันหรือหักสต็อกซ้ำ
- การคำนวณขาดผลิต/การกันให้ครบออเดอร์ก่อนรับส่วนเกินเข้าสต็อกยังใช้ยอดผ่าน QC ที่จัดสรรแล้ว การรอติดตาข่ายไม่สร้างยอดสั่งปั๊มเพิ่มและไม่กักส่วนเกินที่โรงงานมีสิทธิ์รับเข้าสต็อกเพียงเพราะยังติดตาข่ายไม่เสร็จ
- บันทึกและย้อนยอดมี request id และตรวจคำขอซ้ำ/ฟอร์มค้าง ย้อนโดยเก็บประวัติ ไม่ลบรายการทิ้ง การย้อนยอดติดเสร็จลดพร้อมส่งและเพิ่มรอติดตาข่ายตามจริง
- ห้ามลด แก้เอกลักษณ์ ยกเลิก หรือเปลี่ยนเกรด/ปลายทางของแหล่งจัดสรร QC ที่ถูกใช้ติดตาข่ายแล้วจนต่ำกว่ายอดที่ใช้ ต้องย้อนยอดติดตาข่ายส่วนที่เกี่ยวข้องก่อน แล้วใช้ขั้นแก้ QC/จัดสรรเดิม หากพบของเสียตอนติดตาข่ายก็แก้ต้นทางตามลำดับนี้ ไม่สร้างยอดดีหรือของเสียซ้ำในบันทึกติดตาข่าย
- การแก้ QC/จัดสรรทั้งเส้นทางงานเตาใหม่และงานเดิม รวมการบันทึกติดตาข่าย ต้องตรวจยอดใน transaction/การล็อกที่ป้องกันการทำพร้อมกัน ต้องไม่เกิดการติดตาข่ายเกินยอดจากสองหน้าจอ

รายละเอียดที่ผู้พัฒนาต้องรักษา: การจัดสรรของงานเตาใหม่เป็น projection ที่ลบและเขียนใหม่ภายใน transaction จึงต้องรักษาตัวอ้างอิงเชิงตรรกะและตรวจข้อผูกพันกับงานติดตาข่ายหลัง projection เสร็จก่อน commit ไม่ cascade ลบประวัติติดตาข่ายตามแถว projection ห้ามเปลี่ยน ready/missing ใน view เดิมทั้งหมดจนทำให้การกันยอดผลิตและกติกาส่วนเกินใช้ยอดรอติดตาข่ายเป็นของขาดผลิต ต้องแยกความหมายยอดจัดสรร ยอดรอติดตาข่าย และยอดพร้อมส่งให้ชัด

ข้อเสนอรายละเอียดเพื่อให้ตรวจพร้อมแบบ: เพิ่มส่วนรอติดตาข่ายและบันทึกเสร็จในหน้า QC ใช้ finishing.read สำหรับดู, finishing.allocate สำหรับบันทึกยอดติดเสร็จ และ finishing.correct สำหรับย้อนรายการตามสิทธิ์เดิม แสดงยอดลูกค้าสั่ง ผ่าน QC ที่กันไว้ รอติดตาข่าย ติดเสร็จ และพร้อมส่ง ใช้ข้อมูลใบสั่งและผู้บันทึกเดิม ไม่เพิ่มทะเบียนพนักงานติดตาข่ายหรือระบบส่งสินค้าใหม่

## การนำเข้าและข้อมูลเดิม

- ตรวจไฟล์ใหม่และสร้างรายงาน mapping ส่วนตัวก่อนเขียน ตรวจว่ามี 161 รายการ / 152 รหัสตามรุ่นที่ตรวจ ไม่ใช้เลข id ของเอกสารเป็น primary key ฐาน
- เก็บเอกลักษณ์แหล่งนำเข้าและ mapping ต่อแถวเพื่อให้รันไฟล์เดิมซ้ำแล้วไม่เพิ่มรายการซ้ำ หากไฟล์เปลี่ยนหรือชน mapping ให้รายงานผลต่างและหยุดส่วนที่ขัดกัน ไม่ fuzzy match หรือรวมรหัสให้เอง
- ขั้นนำเข้าทะเบียนสร้าง/แก้เฉพาะข้อมูลที่ตรวจรับ ไม่สร้างงานปั๊ม ใบเบิก การทำสี เตา QC หรือยอดคงเหลือจากไฟล์สินค้า ช่องว่างต้นทางไม่ล้างค่าที่หน้างานยืนยันไปแล้ว
- ฐานหลักที่อ่านเมื่อเริ่มหารือมีประเภทผลิต id 6/7 ขนาด 2×8 ดินแดง/ขาว มีสามใบสั่งและแหล่งสต็อก/ใบเบิกแล้ว รักษา id และ foreign keys ทั้งหมด ไม่รวมสอง id เป็นรายการเดียว
- ยังไม่มีหลักฐานว่ารายการเดิมตรงกับสินค้ารุ่นไม่ระบุหนาหรือรุ่น 20 มม. จึงไม่ผูกกับรหัสในไฟล์ด้วยขนาดอย่างเดียว การจับคู่ทำในขั้นตรวจข้อมูล QA โดยผู้ใช้/หน้างานยืนยัน หากยังไม่ทราบให้รายการเดิมทำงานต่อแบบ legacy พร้อมป้ายยังไม่จับคู่ โดยไม่สร้างสินค้าสมมติปนใน 161 รายการ

## เปลี่ยนชื่อดิน

ชื่อมาตรฐานในทะเบียน ฟอร์ม API และค่าที่ใช้คำนวณ/ตรวจเท่ากันเป็นศิลาแลง ต้องตรวจทั้ง CHECK constraints ค่าดินในใบสั่ง สต็อก ใบเบิก ชุดชุบ รอบเผา ผลรับสต็อก การจัดสรร และสถานะงานเตาที่เกี่ยวข้อง ไม่แก้เฉพาะ label

รักษา audit และ payload ของคำขอเดิมตามที่บันทึกเพื่อไม่ทำลายหลักฐานหรือ idempotency ประวัติที่มีชื่อเก่าแสดงชื่อปัจจุบันพร้อมบอกชื่อเดิมได้ การส่งชื่อเก่าจากฟอร์มค้างต้องได้รับข้อความให้โหลดล่าสุดหรือกติกา alias ที่ประกาศชัด ไม่รับแล้วเปลี่ยนเป็นดินอื่น สคริปต์ย้ายต้องรันซ้ำได้และตรวจเป้าหมายจริงก่อนทุกครั้ง

## สิทธิ์และหน้าจอ

ใช้เมนูหมวดหมู่ → ทะเบียนกระเบื้องและสิทธิ์ดู/จัดการงานปั๊มเดิม ค้นด้วยรหัส ชื่อ และรายละเอียด แสดงรายการรหัสซ้ำให้เห็นความหนา/การติดตาข่าย ส่วนรายละเอียดมีแบบดินปั๊มที่เชื่อมและค่าผลิตรายดิน สินค้าที่ใช้พื้นร่วมแสดงความสัมพันธ์ให้ตรวจได้

ตัวอย่างข้อความในใบสั่ง: สินค้า [รหัสและชื่อ] → ดิน [แดง/ขาว/ศิลาแลง/สี] → สีดิน [เมื่อเลือกดินสี] → สีเคลือบ [เมื่อผ่านงานสี] → จำนวนและเผื่อ ระบบแสดงเหตุผลของรายการที่ยังเปิดผลิตไม่ได้ และรักษาการใช้งานจอมือถือ

## การทดสอบและเปิดใช้

ก่อน migration/test ที่เขียนข้อมูล สำรอง lthai ใน lthai-docker ใหม่พร้อม checksum กู้เป็นฐาน QA แยกและตรวจ current_database/connection ก่อนเริ่ม แอป QA ใช้ฐานนี้เท่านั้น

ตรวจนำเข้าครบและซ้ำไม่เพิ่ม คงรหัสซ้ำ/ชื่อซ้ำ มิติเดียวและทศนิยม ช่องว่างไม่ล้างค่า การกั้นผลิตเมื่อค่ารายดินไม่ครบ สีดินต่างกันไม่ปน กองดินพื้นใช้ร่วมได้เฉพาะที่จับคู่แล้ว และสินค้าหลังทำลายต่างรหัสไม่รวม ตรวจศิลาแลงตั้งแต่ทะเบียนผ่านเตาและประวัติ รวมถึงฟอร์มค้างและคำขอซ้ำ

ตรวจใบสั่งติดตาข่ายเลือกได้เฉพาะรุ่นที่รองรับและต้องมีออเดอร์ลูกค้า ผ่าน QC/จัดสรร 1,000 แผ่น ติดเสร็จ 400 แผ่น ต้องแสดงรอติดตาข่าย 600 พร้อมส่ง 400 แผ่น บันทึกซ้ำต้องไม่เพิ่มยอด ทดสอบติดเกิน การทำพร้อมกัน การย้อนยอด การลด QC/จัดสรรที่ถูกใช้แล้ว การเปลี่ยนเกรด และ projection เขียนใหม่โดยไม่ทำประวัติหาย งานไม่ติดตาข่ายต้องได้ยอดพร้อมส่งตามเดิม และส่วนเกินต้องยังรับสต็อกได้เมื่อกัน QC ให้ออเดอร์ครบแล้วแม้งานติดตาข่ายยังไม่ครบ

ตรวจแก้ทะเบียนแล้วใบเดิม/ยอดเดิมไม่เปลี่ยน รักษา id/FK และ fingerprint ข้อมูลเดิมที่ไม่เกี่ยวข้อง ตรวจ API build/typecheck และ browser บน QA ตามขอบเขต ไม่รันชุดทดสอบที่เขียนลง lthai

เมื่อผู้ใช้ตรวจรับโมดูลและข้อมูลที่จะเก็บแล้ว สำรองหลักใหม่ ใช้ migration และ selected-data mapping กับหลักปัจจุบันโดยรักษาความเปลี่ยนแปลงหลังสำเนา QA ห้าม restore QA ทับหลัก ตรวจหลักและเก็บสำรอง QA ก่อนลบทรัพยากร QA ให้เหลือ lthai-docker ชุดเดียวตาม AGENTS.md

## รายละเอียดที่ผู้พัฒนาตัดสินใจได้

ชื่อ table/column เส้นทาง API และโครงสร้าง component เลือกให้เข้ากับ repo โดยต้องรักษาเอกลักษณ์และกติกาข้างต้น สามารถคง pressing_types เป็นตัวอ้างอิงประเภทผลิตเดิมและเพิ่มความสัมพันธ์สินค้า/แบบดินปั๊มได้ ไม่บังคับเปลี่ยน primary key หรือสร้าง ledger การผลิตใหม่ เลือกการจัดเก็บขนาดมิติเดียวให้รองรับการแสดงผลและคำนวณด้วยอัตราหน้างาน ห้ามเติมตัวเลขให้ผ่าน schema เดิมอย่างเดียว
