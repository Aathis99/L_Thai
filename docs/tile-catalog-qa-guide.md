# ตรวจรับทะเบียนกระเบื้องรุ่น QA

รุ่นทดสอบแยกจาก Docker หลัก ใช้ฐาน `lthai_tile_catalog_qa` เว็บเป้าหมาย [http://127.0.0.1:3150](http://127.0.0.1:3150) ส่วนเว็บหลักยังเป็นพอร์ต 3001 สถานะการเปิดและผลตรวจล่าสุดดูใน CURRENT.md

ใช้บัญชีโรงงานตามสำเนาวันที่ 20 พฤศจิกายน 2026 หรือบัญชีเฉพาะ QA ในไฟล์ส่วนตัว `D:/LThai/.qa/tile-catalog/login.json` มีบัญชีผู้ดูแลทดสอบและดูอย่างเดียว รหัสผ่านไม่อยู่ใน Git

## ข้อมูลที่ให้ตรวจ

- รายการต้นทางครบ 161 รายการ / 152 รหัส รวมรุ่นติดตาข่าย 6 รายการ รายการจริงยังรอตรวจแบบดินปั๊มและค่าผลิต ไม่มีการเดาแผ่นต่อไม้ วันพัก หรือจำนวนสต็อก
- มีสินค้าสังเคราะห์เพิ่ม 2 รายการชื่อขึ้นต้น QA-DEMO จึงแสดงรวม 163 รายการ ค่าของตัวอย่างใช้ทดสอบเท่านั้น: 100 แผ่นต่อไม้ พัก 0 วัน และ 100 แผ่นต่อ ตร.ม. ไม่ใช่ค่าที่รับรองให้สินค้าจริง
- ตัวอย่างใช้ดินทั้งสี่ชนิด และแยกดินสีฟ้า/เขียวไว้ให้ตรวจการเลือกสีดิน
- ประเภทเดิม id 6/7 และข้อมูลที่มีประวัติยังอยู่ ไม่จับคู่กับสินค้ารุ่นใดในไฟล์ให้เอง

## ทะเบียนและใบสั่ง

1. เปิด หมวดหมู่ → ทะเบียนกระเบื้อง ค้น LT-428 ต้องเห็นแยกสองรายการตามความหนา ค้น LT-G002 เพื่อตรวจขนาดวงกลมที่มีมิติเดียว
2. เลือกสินค้าที่ตรวจชิ้นงานแล้ว จึงสร้างหรือเชื่อมแบบดินปั๊ม กำหนดค่าผลิตตามดินและสีดินเมื่อเกี่ยวข้อง สินค้าหลายลายเชื่อมแบบแผ่นพื้นเดียวกันได้เมื่อหน้างานยืนยัน
3. เปิด งานปั๊ม → ใบสั่งผลิต เลือกสินค้ารุ่นที่ต้องการ แล้วเลือกดิน/สีดิน สีเคลือบตามเส้นทาง และจำนวนสินค้า รุ่นติดตาข่ายต้องมีออเดอร์ลูกค้า
4. การปั๊มแผ่นพื้นเก็บสต็อกเลือกประเภทผลิตได้โดยไม่ต้องผูกสินค้าปลายทาง จากนั้นเบิกให้ใบสั่งปลายทางตามกติกาการกันยอดเดิม

## ทดลองติดตาข่าย

เปิด ตรวจสอบคุณภาพ(QC) → งานปัจจุบัน → QC จะพบงาน QA-TILE-MESH-DEMO ใบสั่ง #9 ตัวอย่างกันแผ่นจาก QC 1,000 แผ่น ติดเสร็จ 400 แผ่น จึงรอติด 600 และพร้อมส่ง 400 แผ่น

บันทึกติดเสร็จเพิ่ม 100 แผ่นแล้วตรวจรอ 500 / พร้อมส่ง 500 จากนั้นย้อนรายการ 100 แผ่นพร้อมเหตุผล ยอดควรกลับไปรอ 600 / พร้อมส่ง 400 ประวัติแสดงต้นทาง QC/เกรดที่ใช้และรายการที่ย้อนแล้ว จำนวนทั้งหมดนับเป็นแผ่นกระเบื้องย่อย

บัญชีดูอย่างเดียวค้นทะเบียนและดูยอดได้ แต่ไม่มีปุ่มเพิ่ม แก้ไข บันทึกติดเสร็จ หรือย้อนรายการ

## หลังตรวจรับ

แจ้งรายการและค่าจริงที่จะเก็บก่อนนำขึ้นหลัก การขึ้นหลักต้องสำรองฐานหลักใหม่และย้ายเฉพาะโค้ด/migration/ข้อมูลที่ยืนยัน โดยรักษางานที่เปลี่ยนหลังสำเนา QA ไม่กู้ทั้งฐาน QA ทับหลัก ตัวอย่าง QA-DEMO และบัญชี/พนักงานทดสอบจะไม่ถูกนำขึ้นหลักโดยอัตโนมัติ
