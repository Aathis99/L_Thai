# ตรวจรับระบบรับดินใน QA

เว็บทดสอบ: http://127.0.0.1:3170 — ระบบหลักยังอยู่พอร์ต 3001

บัญชีทดสอบและรหัสผ่านอยู่ในไฟล์ส่วนตัว `.qa/clay-receiving/review-account.txt` ใช้เฉพาะ QA ไม่ใช่บัญชีระบบหลัก

ตรวจล่าสุด 26 พฤศจิกายน 2026: API159ผ่าน/9ข้าม/0ล้ม เว็บ79ผ่าน legacy14ผ่าน TypeScriptและ Docker buildผ่าน ตรวจหน้าจอและการรับ–เบิก–ตรวจนับ–แก้/ยกเลิกใน QAแล้ว ระบบหลัก3001ยังไม่ได้นำโมดูลนี้ขึ้นใช้

## ข้อมูลสำหรับลอง

เปิดเมนู **รับดินและวัตถุดิบ** แล้วเลือก **รับเข้า** กรองสถานะ **ยืนยันแล้ว** จะเห็นตัวอย่างดินขาวหกรายการจาก Markdown เดิม ตัดทรายออก ชื่อดินตามเอกสารต่างกันแต่ยอดรวมอยู่ประเภทดินขาวเดียวกัน ตรวจยอดต้นทางได้จากไฟล์ส่วนตัว `.qa/clay-receiving/seed-result.json`

ข้อมูลวันในบิล ชื่อและปริมาณที่มีใน Markdown เป็นข้อมูลตัวอย่างต้นทาง ส่วนเวลาชั่ง น้ำหนักรถ ทะเบียนรถ ผู้รับ และภาพถูกเติมเพื่อจำลองและระบุไว้ในหมายเหตุ ภาพมีข้อความ QA SIMULATION ไม่ใช่ภาพบิลผู้ขายจริง ยอดนี้ใช้ทดสอบ ไม่ใช่คงเหลือจริงของโรงงาน

รายการชื่อ QA-SMOKE/QA-PROXY ที่ยกเลิกแล้วเป็นประวัติการตรวจระบบ ไม่มีผลต่อยอดคงเหลือ กรองสถานะเพื่อแยกจากรายการรับตัวอย่างได้

## ลองตามลำดับ

1. เปิดใบรับตัวอย่าง ตรวจว่าผู้ขาย ชื่อดิน และจำนวนถูกต้อง ชั่งเข้าเป็นรถเปล่าที่ผู้ขาย ชั่งออกเป็นรถพร้อมดิน และเวลารับโรงงานเป็นอีกเหตุการณ์ เปิดดูภาพและประวัติฉบับได้
2. เปิด **สต็อกวัตถุดิบ** ตรวจว่าตัวอย่างทุกชื่อรวมเป็นดินขาวเดียวกัน ลองกรองช่วงวันที่ ดูยอดยกมา/รับ/เบิก/ปรับ/คงเหลือปลายช่วง
3. เพิ่มใบรับใหม่ บันทึกร่างก่อนแล้วตรวจว่ายอดยังไม่เพิ่ม เมื่อตรวจข้อมูลและแนบภาพ 1–3 รูปครบจึงยืนยัน ยอดดินขาวเพิ่มตามสุทธิ ไม่เพิ่มประเภทจากชื่อการค้า
4. น้ำหนักรถพร้อมดินต้องมากกว่ารถเปล่า และผลต่างต้องตรงสุทธิ ลองข้อมูลไม่ตรงเพื่อตรวจข้อความแก้ไข ช่องที่เอกสารไม่มีเว้นพร้อมหมายเหตุได้ ไม่สร้างค่าชั่งแทนข้อมูลที่หาย
5. เลือก **เบิกเข้าโม่** กรอกประเภทดิน จำนวนกิโลกรัม วันเวลาและผู้เบิก ยืนยันแล้วลดยอดประเภทนั้น ลองเบิกเกินยอดเพื่อตรวจการปฏิเสธ ร่างและรายการผิดไม่ควรเปลี่ยนยอด
6. เลือก **ปรับยอดและประวัติ** ระบุยอดตรวจนับจำลอง เหตุผลและผู้ตรวจ ระบบเก็บยอดก่อน/หลังพร้อมผลต่าง โดยไม่แก้ข้อเท็จจริงใบรับเดิม
7. แก้ใบรับที่เกิดก่อนการตรวจนับ พร้อมเหตุผล ตรวจว่ายอดตรวจนับยังคงเดิมและผลต่างปรับเปลี่ยนตามข้อมูลใหม่ เปิดประวัติจากทั้งใบรับและรายการตรวจนับได้
8. ลองแก้/ยกเลิกรับหรือเบิก ตรวจเหตุผล ประวัติและผลย้อนยอด การแก้ที่ทำให้ยอดในประวัติหรือปัจจุบันติดลบต้องไม่ผ่าน
9. เปิดใบเดียวกันสองหน้าต่าง ลองแก้จากอีกหน้าแล้วกลับมาบันทึกหน้าเก่า ต้องตรวจข้อมูลล่าสุดและแก้ความขัดแย้งก่อน ไม่มีการทับการแก้ของอีกคนโดยเงียบ ๆ

## ภาพและวันเวลา

ใช้รูปนิ่ง JPEG/PNG/WebP ไม่เกิน 8 MiB ต่อรูป ร่างมี 0–3 รูปได้ แต่ยืนยันต้องมี 1–3 รูป ระบบบีบอัดก่อนเก็บและเปิดภาพเมื่อกดดู ฉบับเก่ายังมีภาพให้ตรวจย้อนหลัง ภาพที่เก็บถูกแปลงแล้ว จึงควรลองรูปบิลจริงที่อ่านตัวเลขเล็กชัดก่อนตรวจรับ

เวลาใช้วันที่และช่องชั่วโมง 00–23/นาที 00–59 แยกเวลาชั่งผู้ขาย เวลารับโรงงาน และเวลาบัญชีบันทึก เวลาในอดีตกรอกตามเหตุการณ์ได้ ส่วนปรับยอดใช้เวลายืนยันปัจจุบัน

ช่องน้ำหนักเลือกกรอกกิโลกรัมหรือตันได้ ระบบแปลงด้วย 1 ตัน = 1,000 กิโลกรัมและไม่ปัดหน่วยย่อยทิ้ง ยอดตั้งแต่ 1,000 กิโลกรัมแสดงค่าตันประกอบ ยอดตรวจนับและรายการในนาทีเดียวกันเรียงลำดับยืนยัน โดยเก็บเวลาบัญชีทำรายการเต็มไว้ในประวัติ

## หลังตรวจรับ

แจ้งส่วนที่ต้องปรับและข้อมูลที่จะเก็บขึ้นหลัก การอนุมัติทดสอบนี้ยังไม่ย้ายข้อมูลจำลองขึ้นหลัก เมื่ออนุมัติ code/migration/ข้อมูลแล้ว ต้องสำรองหลักสดอีกครั้งและย้ายเฉพาะที่ตกลง ไม่ restore QA ทับฐานหลัก ตาม AGENTS.md

ระหว่างรอการตรวจรับเก็บ QA นี้ไว้ให้ลอง ส่วนฐานทดสอบชั่วคราวสำหรับชุดทดสอบเดิมแยกจากฐาน QA ของโมดูลและถอดเมื่อรันเสร็จ
