# บันทึกความต้องการระบบโรงงานกระเบื้อง

สถานะ: เริ่มส่วนพนักงานและสิทธิ์ตามคำสั่งผู้ใช้ ส่วนผลิตยังเก็บความต้องการ
วันที่เริ่ม: 2026-11-09

## ข้อมูลจากผู้ใช้

- เป้าหมายระยะยาวคือโปรแกรมจัดการโรงงานกระเบื้องครบวงจร
- เริ่มทำเป็นส่วนเล็ก ๆ ตามข้อมูลที่มี แล้วเพิ่มรายละเอียดภายหลัง
- ขั้นตอนที่ทราบในตอนนี้: ส่งดินปั้น → ปั๊มขึ้นรูป → ทาสี
- กระเบื้องแต่ละประเภทอาจใช้ขั้นตอนการผลิตต่างกัน โดยบางประเภทเว้นบางขั้นตอน
- ต้องเก็บข้อมูลประเภทกระเบื้อง
- ต้องมีระบบเข้าสู่ระบบ และการเพิ่ม ลบ แก้ไขข้อมูลคนและตำแหน่ง ทั้งนี้ขอบเขตสิทธิ์ยังต้องสอบถาม

## ประเด็นที่ต้องทำความเข้าใจ

- ปัญหาหลักและผลลัพธ์ที่ต้องการจากรุ่นแรก
- วิธีเรียกและติดตามงานจริง: รายชิ้น รายชุด/ล็อต หรือยอดรวม
- ความหมายของส่งดินปั้น ผู้ส่ง ผู้รับ และหน่วยนับ
- ตัวอย่างเส้นทางผลิตจริง และเงื่อนไขการเว้นขั้นตอน
- ผู้บันทึกข้อมูล ผู้ตรวจสอบ และผู้ดูแลข้อมูลคน
- ความต่างระหว่างตำแหน่งงานกับสิทธิ์ใช้งานระบบ
- ข้อมูลจำนวนดี เสีย ค้าง และการส่งงานบางส่วน จำเป็นในรุ่นแรกหรือไม่
- อุปกรณ์ จุดใช้งาน และความพร้อมของอินเทอร์เน็ต

## คำตอบรอบแรก

- ปัจจุบันจดข้อมูลหน้างานแล้วนำมากรอก Excel ซ้ำ ต้องการกรอกที่หน้าของแต่ละขั้นตอนในระบบเดียว และเชื่อมข้อมูลให้ผู้ใช้อื่น
- เมื่อมีการเบิกไปทำ ต้องลดจำนวนที่เกี่ยวข้อง รายละเอียดหน่วยนับและกติกาหักยอดรอข้อมูล Excel
- งานผลิตต้องมีคำสั่งก่อน ในรอบแรกเรียกว่า “ออเดอร์” และในรอบสองตกลงใช้คำว่า “ใบสั่งผลิต” แยกจากออเดอร์ลูกค้า วิธีแบ่งงานย่อยหรือเลขล็อตยังรอยืนยัน
- บางประเภทกระเบื้องเว้นบางขั้นตอนถาวร แต่ข้อมูลยังไม่ชัด รอสอบถามเพิ่ม
- บางขั้นตอนธุรการเป็นผู้ไปจดและนำมากรอก Excel จึงห้ามสมมติว่าผู้บันทึกคือผู้ปฏิบัติงาน
- ผู้ใช้ขอให้บันทึกคำถามไว้และเริ่มระบบเข้าสู่ระบบ ตรวจสิทธิ์ และเพิ่ม/ลบ/แก้ไขก่อน มีข้อมูลพนักงานใน Excel อยู่แล้ว
- ขณะสำรวจยังไม่พบ Excel ใน D:/LThai จึงยังไม่นำเข้าหรือเดาชื่อคอลัมน์

## สิ่งที่รอข้อมูลเพิ่มเติม

- ไฟล์ Excel พนักงาน: หัวคอลัมน์ รหัสพนักงาน ตำแหน่ง แผนก และข้อมูลซ้ำ
- Excel งานผลิต: ออเดอร์ รายการเบิก หน่วยนับ จำนวน และการส่งต่อ
- รายชื่อประเภทกระเบื้องและขั้นตอนที่แต่ละประเภทต้องผ่าน
- ผู้ใช้งานจริงแต่ละหน้ากับสิทธิ์ที่เหมาะสม

## ข้อเสนอที่ยังไม่ได้ตกลง

- ยังไม่มีการกำหนดรูปแบบล็อต ขั้นตอน สิทธิ์ หรือเทคโนโลยีแทนผู้ใช้
- ไม่ถือว่าการข้ามขั้นตอนตามประเภทคือการข้ามขั้นตอนหน้างานเป็นกรณีพิเศษ ทั้งสองเรื่องต้องแยกสอบถาม

## รอบเลือก stack และไฟล์พนักงาน

- ผู้ใช้ต้องการปรึกษาและเปลี่ยน stack โดยชอบ React / Next.js / TypeScript
- จะมีหลายคนใช้ในโรงงานผ่านมือถือและคอมพิวเตอร์ เน้นดูแลง่ายและขยายระบบโรงงานได้
- เสนอ Next.js + TypeScript + PostgreSQL เป็นแอปเดียวที่แยกโมดูลภายใน เทียบกับ Next.js + NestJS API แยกแอป รอผู้ใช้เลือกแนวทางและสถานที่รันระบบจริง
- ได้รับ Excel แล้ว ชีตที่ผู้ใช้ระบุคือ “พนักงาน ปี2569” มีพนักงาน 36 คน แถวข้อมูล 3–38 ไม่มีลำดับหรือชื่อซ้ำ ไม่มีหมายเหตุพนักงาน
- หัวคอลัมน์มีลำดับ คำนำหน้า ชื่อ นามสกุล อายุ วันเกิด เลขบัตร/เลขผู้เสียภาษี ที่อยู่ รหัสไปรษณีย์ โทรศัพท์ วันที่เริ่มงาน และหมายเหตุ ไม่มีรหัสพนักงาน แผนก หรือตำแหน่ง
- บางรายการไม่มีนามสกุล ให้คงข้อมูลที่มีโดยไม่แต่งเติม
- เสนอรหัสชั่วคราว EMP69-001 ถึง EMP69-036 และนำชื่อ/โทรศัพท์ก่อน หรือขยายเป็นประวัติทั้งหมดตามความต้องการ รอคำตอบผู้ใช้
- ตรวจพบ Docker Desktop ติดตั้งอยู่ แต่ engine ยังไม่ทำงาน ยังไม่เริ่มหรือแก้ค่าระบบแทนผู้ใช้

## ข้อสรุปที่ผู้ใช้เลือก

- Next.js หน้าบ้าน + Node.js/Express API + PostgreSQL และใช้ DBeaver จัดการฐานข้อมูล
- มีหรือเตรียมเครื่องในโรงงานได้ ต้องทำงานผ่าน LAN/Wi-Fi ต่อได้เมื่ออินเทอร์เน็ตล่ม
- ใช้รหัสชั่วคราว EMP69-001 ถึง EMP69-036
- นำเข้าชื่อและเบอร์โทรก่อน ไม่ดึงวันเกิด เลขบัตร ที่อยู่ หรือประวัติส่วนตัวอื่น แผนกและตำแหน่งค่อยเติม

- ตารางปั๊มที่สำรวจไม่มีคอลัมน์เลขออเดอร์ วิธีเชื่อมใบสั่งผลิตกับรายการปั๊มและออเดอร์ลูกค้ายังรอยืนยัน
- ยังไม่สรุปว่ายอดในส่วนบรีสของไฟล์สต็อกนับกระเบื้องที่ขั้นตอนไหน วิธีตามงานถึงผู้ปั๊มและสิทธิ์ผู้ใช้งานยังรอรายละเอียด

- หัวคอลัมน์สต็อกใน Excel ที่สำรวจมีชื่อ “ศิลาแลง” ส่วนรายการจากหน้างานมี “จ้อ” จึงเก็บเป็นจุดรอเทียบก่อนใช้ยอดตั้งต้น
- บันทึกยอดปั๊มแล้วเพิ่มสต็อกทันที แสดงช่วงรอเซ็ตตัวและกำหนดครบวันพักตามประเภท ผู้เบิกตรวจของจริงและระบบลดสต็อกเมื่อยืนยันเบิก
- บันทึกยอดปั๊มตามจริงแม้เกินเป้าเพื่อให้เต็มไม้ ให้ผู้รับผิดชอบตัดสินใจว่าจะปล่อยส่วนเกินไปใช้กับงานอื่นเมื่อไร ตัวอย่างยอดสั่ง 1,000 แผ่นกับยอดปั๊ม 1,500 แผ่นมีส่วนเกิน 500 แผ่น

## แนวทางงานปั๊มที่ผู้ใช้เลือก 2026-11-11

- รุ่นแรกตามใบสั่งผลิตและรายการปั๊ม โดยใช้วันที่ ผู้ปั๊ม และการเบิกที่ยืนยันได้ เชื่อมผลคัดกับงานเผาตามข้อมูลที่หน้างานมี การติดเลขชุดตลอดเส้นทางต้องให้หน้างานรักษาป้ายและแยกชุดในแต่ละขั้นตอน จึงใช้แนวทางที่เข้ากับการจดปัจจุบันก่อน
- ผู้ใช้ยืนยัน [แบบระบบงานปั๊มรุ่นแรก](superpowers/specs/2026-11-11-pressing-design.md) แล้ว ลำดับการพัฒนาอยู่ใน [แผนพัฒนางานปั๊ม](superpowers/plans/2026-11-11-pressing.md)

## ชาร์ตสี

- ผู้ใช้ต้องการนำชาร์ตสีจาก Excel มาตั้งต้นทะเบียนที่เพิ่ม ลบ และแก้ไขชื่อสีกระเบื้องได้ พร้อมช่องอัปโหลดภาพตัวอย่างในอนาคต ปัจจุบันยังไม่มีภาพ
- ตรวจไฟล์แบบอ่านอย่างเดียว พบรายการมีลำดับ 1–90 ที่ `Sheet1!A3:B92` ชื่อส่วนใหญ่เป็นภาษาไทยตามด้วยชื่ออังกฤษในวงเล็บ มีทั้งรายการดินที่เคลือบใสและรายการชื่อเดียวกันที่ไม่เคลือบแยกคนละลำดับ ลำดับ 64 คือ “วาดลาย” และ `B95:B96` เป็นหมายเหตุการเผา
- ผู้ใช้ยืนยันให้นำเข้าครบ 90 รายการ รวม “วาดลาย” โดยเก็บรายการเคลือบใสแยกจากรายการเดิม ใช้ชื่อเต็มตาม Excel และใช้ลำดับเดิมในการแสดงผล
- หนึ่งรายการมีภาพตัวอย่างได้หนึ่งภาพ และบันทึกชื่อไว้ก่อนได้แม้ยังไม่มีภาพ
- ผู้ใช้ให้เก็บหมายเหตุการเผาไว้เป็นข้อมูลเตือน เสนอแสดงข้อความอ้างอิงต้นฉบับในหน้ารายละเอียดของขาวฟ้า เขียวศิลาดล และศิลาดล
- ผู้ใช้เลือกเก็บภาพตัวอย่างใน PostgreSQL เพื่อให้ติดไปกับชุดสำรอง Docker [เหตุผลที่เลือก](adr/0003-color-chart-images-in-postgres.md) และ [แบบระบบชาร์ตสีรุ่นแรก](superpowers/specs/2026-11-12-color-chart-design.md)
- ผู้ใช้ยืนยันแบบแล้ว ลำดับลงมือและการตรวจรับอยู่ใน [แผนพัฒนาชาร์ตสี](superpowers/plans/2026-11-12-color-chart.md)
