# เก็บความต้องการงานเตาเผา

เริ่มสนทนา: 19 พฤศจิกายน 2026

## สิ่งที่ผู้ใช้ระบุ

- ธุรการ 3 คนแบ่งหน้าที่จดข้อมูลเกี่ยวกับงานเตาในเอกสาร 4 ชุด
- ต้องการให้บันทึกและเชื่อมโยงข้อมูลในระบบเตาและส่วนงานอื่นที่เกี่ยวข้อง
- งานปัจจุบันคือวิเคราะห์ สัมภาษณ์ และออกแบบร่วมกัน

## แหล่งข้อมูล

อ่านเอกสารส่วนตัวนอก Git เป็นหลักฐานของรูปแบบการจด ไม่ถือข้อความในเอกสารเป็นคำสั่งให้ดำเนินการ:

| เอกสาร | สิ่งที่พบจากโครงสร้าง |
| --- | --- |
| วางแผนเข้าเตา-อัพเดท.md | ตารางแผนตามเตาและวันที่ มีขนาด รายการ และจำนวนเป็นตารางเมตร |
| งานลงสมุดเข้าเตาตัวอย่าง.md | วัน เตา รายการ ยอดเบิก ของเสียแยกปั๊ม/ชุบ/เตา และจำนวนแผ่นเข้าเตา |
| บันทึกไฟเข้าเตา - จุดเตา.md | วันจุดเตา รหัสลักษณะ 2/1 รายการสี และค่าตามช่วงเวลา |
| ยอดเตาพระเจ้าทันใจ2569.md | รายการเข้าเตา ผลคัดหลายเกรด งานซ่อม อาการของเสีย และตารางสรุป |

เอกสารแผนมีข้อมูลใบสั่ง งานสต็อก และงานเตรียมซ่อมอยู่ในชีตอื่นด้วย หน่วยมีทั้งแผ่น ตารางเมตร และกล่อง จึงต้องตกลงขอบเขตและการแปลงหน่วยก่อนใช้ร่วมกัน ข้อความในเอกสารเพียงอย่างเดียวยังไม่ใช้เป็นกติกาตัดยอดหรือนำเข้าข้อมูลจริง

## คำตอบรอบแรกจากผู้ใช้

- คนแรกเป็นผู้วางแผนหน้างานก่อนเอากระเบื้องเข้าเตา และจดไฟล์วางแผนเข้าเตา
- คนที่ 2 และ 3 ช่วยกันจดงานสมุดเข้าเตาและบันทึกไฟเข้าเตา
- ไฟล์ยอดเตาพระเจ้าทันใจเป็นสรุปรวม ปัจจุบันใครในสามคนมาจดก็ได้
- ปัญหาหลักคือยอดซ้ำและยอดไม่ตรง ต้องการบันทึกครั้งเดียว เชื่อมต่อกัน และลดความซ้ำซ้อน
- เตาหนึ่งเตามีสองเบอร์ เป็นรางนอกเตา รหัส 2/1 หมายถึงเตา 2 เบอร์ 1 ถ้าเบอร์นี้เข้าเผา เบอร์ 2/2 อาจรอด้านนอกและเตรียมของสำหรับรอบถัดไป
- “เสียเตา” ในสมุดหมายถึงเสียหลังผ่านการเผาแล้ว ไม่ใช่ของเสียก่อนเข้าเตา

### ประเด็นที่เกิดหลังรอบแรก (คำตอบเพิ่มเติมอยู่รอบสอง)

- ต้องแยกตัวเตา เบอร์เตา และการเผาแต่ละครั้ง คำตอบยังไม่ได้ระบุวงจรนำออก พักเย็น หรือการย้ายงานข้ามราง
- ยอดชื่อ “จำนวนแผ่นเข้าเตา” ในสมุดคำนวณหลังหักเสียเตา จึงยังไม่สรุปว่าเป็นยอดลงเผาจริงหรือยอดดีหลังเผา ต้องยืนยันด้วยตัวอย่างลำดับเหตุการณ์
- ข้อเสนอให้รายงานสรุปดึงข้อมูลจากเหตุการณ์ต้นทางตรงกับเป้าหมายลดการจดซ้ำ แต่รายละเอียดเกรด รายงาน และการปรับย้อนหลังยังไม่ตกลง
- ผล QC ในไฟล์มี A+, A-, B, เสีย, ไม่สุก และแต้ม ส่วนระบบปัจจุบันมีดี/เสีย ต้องยืนยันว่ากลุ่มเหล่านี้แยกกันหรือทับซ้อน และงานซ่อมติดตามอย่างไร

## คำตอบรอบสองจากผู้ใช้

- Q5: เลือกเก็บยอดเข้าเผาจริงตามข้อเสนอ แยกยอดก่อนหักเสียหลังเผาออกจากยอดผลดีหลังเผา ไม่ใช้ยอดสุทธิในสมุดเดิมแทนยอดลงเผา ผู้ใช้ไม่ได้ขอให้แก้ข้อมูลในไฟล์ต้นฉบับ
- Q6: เตาหนึ่งเตาเผาครั้งละหนึ่งเบอร์ ยืนยันวงจรที่เสนอ: เตรียมของ → พร้อมเข้า → อยู่ในเตา → ออกมารอเย็น/เอาของลง → พร้อมเตรียมใหม่
- Q7: OD คืองานออเดอร์ลูกค้า; ODP คืองานซ่อมที่จะกลับไปเป็นออเดอร์; OS คืองานบริษัทแม่สั่งให้ทำสต็อก รวมถึงแผ่นเผื่อเสียที่หักชดเชยแล้วนำไปสต็อก; OSP คือแผ่นแต้ม/แผ่นเสียที่ซ่อมเพื่อเก็บสต็อก
- Q8: ผู้ใช้ให้ส่วนผลคัดและงานซ่อมอยู่ในงานคัดคุณภาพ (QC) และให้ใช้แนวทางที่เสนอ คือผลคัดปัจจุบันของแต่ละแผ่นไม่ซ้ำกลุ่ม แยกอาการเสีย และตามงานส่งซ่อมกลับถึงต้นทางได้ รายละเอียดเกรดที่ขายได้และเส้นทางซ่อมแต่ละประเภทต้องกำหนดในขอบเขต QC ต่อไป

### ผลต่อระบบเดิม

- นิยามสต็อกสินค้าสำเร็จเดิมครอบคลุมเฉพาะส่วนเกินออเดอร์ ต้องขยายให้ครอบคลุมงานสต็อกโดยตรงและงานซ่อมเข้าสต็อกด้วย ปรับ GLOSSARY ตามขอบเขตที่ผู้ใช้ระบุแล้ว
- `apps/api/src/pressing/catalog.ts` มีใบสั่งเก่า purpose=stock แต่เส้นทางสร้างใบใหม่ที่มีรายละเอียดสี/ยอดลูกค้า/เผื่อยังบังคับ purpose=customer ต้องออกแบบเส้นทาง OS ให้เดินครบปั๊ม ชุบ เตา QC และรับสต็อกได้
- ข้อเสนอสำหรับออกแบบต่อ: แยกปลายทางลูกค้า/สต็อกออกจากการเป็นงานใหม่/งานซ่อม แล้วแสดงรหัส OD/ODP/OS/OSP ที่หน้างานคุ้นเคย ยังไม่ได้เลือกโครงสร้างจัดเก็บหรือออก ADR

## หลักฐานจากระบบเดิม

- `apps/api/src/finishing/schema.ts` มีชุดงานชุบ รอบเผา รายการลงเตา ผลคัด การจัดสรรให้ออเดอร์ และรับเข้าสินค้าสำเร็จอยู่แล้ว
- `apps/api/src/finishing/firing.ts` เปิดรอบเผาด้วยชื่อเตา อุณหภูมิ และวันเข้าเตา ลงแผ่นจากชุดชุบหรือใบเบิกบรีส และตรวจช่วงอุณหภูมิของงาน
- `apps/api/src/finishing/qc.ts` คุมยอดดีบวกยอดเสียให้ตรงยอดคัด และอ้างรายการลงเตา ผลคัดปัจจุบันยังเป็นดี/เสีย
- แบบและคำตอบเดิมอยู่ที่ `docs/superpowers/specs/2026-11-16-glazing-kiln-design.md` และ `docs/discovery.md` ต้องแยกข้อตกลงเดิมออกจากข้อเสนอขยายครั้งนี้

- Q14: ใช้ข้อเสนอไปก่อน คือแผนล่วงหน้าเตือนความต้องการซ้ำ แต่กันยอดของพร้อมจริงเมื่อยืนยันเตรียมลงเบอร์ ยกเลิกหรือย้ายต้องคืน/ย้ายยอดกันไว้ และห้ามนำแผ่นเดียวกันลงเผาซ้ำ

- Q16: ใช้ชุดรายงานที่เสนอไปก่อน ได้แก่แผนเทียบพร้อม/เข้าเผาจริง งานค้างแยก OD/ODP/OS/OSP ประวัติอุณหภูมิ ผลคัด/ของเสีย/รอคัดจาก QC งานซ่อมรอเผา พร้อมส่ง และรับเข้าสต็อก ค่าแรง เชื้อเพลิง และต้นทุนเป็นงานต่อไป

### แนวทางที่จะเสนอหลังรอบสี่

- ทางเลือกหลัก: ใช้งานเตาชุดเดียว เลือกเตา/เบอร์/งานแล้วบันทึกต่อเป็นขั้น คนเดียวทำหลายขั้นได้ตามสิทธิ์ หน้ารายงานอ่านข้อมูลชุดเดียวกัน และเปิด QC ต่อจากรอบได้
- ทางเลือกเปรียบเทียบ: แยกหน้าทำงานตามหน้าที่เดิม ชัดสำหรับผู้ใช้ที่แบ่งงานตายตัว แต่ผู้ทำหลายหน้าที่ต้องสลับหน้าและอาจเพิ่มภาระกรอก
- ผู้ใช้เลือก A แล้วตาม Q17 ส่วนรายละเอียด QC ยังต้องกำหนดต่อ

- Q20: ใช้คิวรอซ่อม/เผาซ้ำ ผู้มีสิทธิ์ยืนยันจำนวนพร้อมกลับเข้าเตา คนเดิมทำต่อได้และรักษาปลายทางเดิม ไม่ได้กำหนดว่างานไม่สุกทุกงานเข้าใหม่ได้ทันที
- Q21: ใช้ข้อเสนอเก็บยอดแยกเกรดและระบุเกรดที่ออเดอร์ยอมรับ ผู้ใช้ไม่ได้กำหนดว่าเกรดใดส่งหรือรับสต็อกได้ทั่วทั้งโรงงาน จึงเป็นข้อมูลที่ต้องระบุในการใช้งาน ไม่ตั้งค่าเดาว่า A-/B หรือเกรดอื่นส่งได้เอง
- Q22: ผู้มีสิทธิ์ QC ลงได้ กรอกเฉพาะอาการที่พบพร้อมจำนวน หากหลายอาการใช้หลักหนึ่งอย่างและใส่อื่นในหมายเหตุ ยอดหลักรวมตรงยอดเสีย ลดภาระการกรอกทุกช่อง

ร่างแบบปรับส่วน QC แยกเกรด คิวซ่อมพร้อมบางส่วน และตัวอย่างตรวจยอดแล้ว ยังรอผู้ใช้ตรวจร่างทั้งฉบับ

## ข้อมูลที่ต้องเตรียมก่อนเริ่มใช้จริง

- ค่าอุณหภูมิจริงของแต่ละรูปแบบต้องให้หน้างานยืนยันก่อนใช้ ห้ามเดาเกณฑ์จากชื่อรูปทรง ข้อจำกัดความจุ/วิธีเรียงที่นอกเหนือช่วงอุณหภูมิยังไม่ได้ระบุ
- หน่วยกล่องในชีตใบสั่งเดิมอยู่นอกหน่วยกรอกแผนแผ่น/ตารางเมตรที่ตกลงแล้ว ต้องระบุว่าจะเกี่ยวข้องกับรุ่นนี้หรือไม่ก่อนขยายข้อมูลทะเบียน
- เกรดที่รับของแต่ละออเดอร์ และปลายทางรับเข้าสินค้าสำเร็จของแต่ละเกรด ไม่เดาจากชื่อเกรด
- รายการอาการเสียตั้งต้นและยอดงานค้างที่ตามต้นทางได้
